builds the theming system on them. **Renaming one after either task starts is a
breaking change** and needs an entry in Decisions plus a note on
`docs/tg/board.md`. Adding a name is not breaking.

### Runtime switching contract

Three independent attributes, all usable on any element (not only `:root`):

| attribute | values | set by |
| --- | --- | --- |
| `data-tg-theme` | `day` (default) · `night` | `themes/day.css`, `themes/night.css` |
| `data-tg-accent` | `blue` `cyan` `green` `orange` `pink` `purple` — omit for the factory accent | `themes/accents/*.css` |
| `data-tg-wallpaper` | `none` `default` `sunset` `meadow` `orchid` `lagoon` `haze` `forest-night` `midnight-blue` `deep-teal` `pine` `plum-night` `ember` `mulberry` | `themes/wallpapers.css` |

Constraint: `data-tg-accent` and `data-tg-wallpaper` must be on the **same
element as, or a descendant of**, the element carrying `data-tg-theme`. The
accent files rely on selector specificity (`[theme][accent]` and
`[theme] [accent]` beat the bare `[accent]`) to pick the night variant.

### Bubble grammar (a rule, not a taste)

Transcribed from tweb `_chatBubble.scss` `.bubble.is-in` / `.bubble.is-out`:

| position | TL | TR | BR | BL |
| --- | --- | --- | --- | --- |
| incoming, middle of group | merged | full | full | merged |
| incoming, first of group | full | full | full | merged |
| incoming, last of group | merged | full | full | **0 + tail** |
| incoming, alone | full | full | full | **0 + tail** |

Outgoing is the mirror image (merged corners on the right). `full` = 15px,
`merged` = 5px. A `last` bubble that cannot carry a tail keeps the full radius
on that corner instead of 0. The tail is 11×20px, overhangs by −8.4px, is
nudged `translateY(1px)`, and is filled with the **flat** `--tg-bubble-in` /
`--tg-bubble-out` — which is why those two stay flat colours even when
`--tg-bubble-out-fill` is a gradient.

## Decisions

- 2026-09-30 **Reference client is Telegram Web K (tweb), not Desktop, iOS or
  Android.** We are building a web client and the thing a reviewer will hold the
  comparison page next to is `web.telegram.org/k/`. The other three are used
  only where tweb computes a value at runtime and therefore has no literal to
  read: the outgoing bubble fill and the selection fills come from tdesktop's
  palette (same Classic theme), the springs from iOS, the bubble-radius
  cross-check and the easing curves from Android.

- 2026-09-30 **Sources are real client source, not screenshots or memory.**
  Everything tagged `[web]`/`[desktop]`/`[ios]`/`[android]` in the CSS was read
  out of: `morethanwords/tweb` (`src/scss/base.scss`, `variables.scss`,
  `partials/_chatVariables.scss`, `partials/_chatBubble.scss`,
  `helpers/themeController.ts`, `config/themePresets.ts`,
  `components/chat/gradientRenderer.ts`, `public/index.html`);
  `telegramdesktop/tdesktop` (`Telegram/Resources/night.tdesktop-theme`,
  `day-blue.tdesktop-theme` — these are zip archives, unzip to get
  `colors.tdesktop-theme`) plus `desktop-app/lib_ui` `ui/colors.palette` for the
  base Classic palette; `TelegramMessenger/Telegram-iOS`
  (`submodules/UIKitRuntimeUtils/Source/UIKitRuntimeUtils/UIKitUtils.m`,
  `submodules/Display/Source/CAAnimationUtils.swift`,
  `submodules/TelegramPresentationData/Sources/DefaultDay*.swift`,
  `DefaultDark*.swift`); `DrKLO/Telegram`
  (`SharedConfig.java`, `ui/Components/CubicBezierInterpolator.java`,
  `Cells/ChatMessageCell.java`). Every token comment names which one.

- 2026-09-30 **Primitive tokens are prefixed `--tg-raw-`.** The three-layer rule
  ("components consume only semantic") is worthless if nothing can check it. The
  prefix turns it into one grep. Cost is one extra `var()` indirection per
  token, which is free. Tailwind maps from the semantic layer anyway, so the
  ugly prefix never reaches a utility class name.

- 2026-09-30 **Motion is expressed as springs first and CSS second.** Telegram
  iOS has exactly three springs and they are literals in one ObjC file:
  standard `m 3, k 1000, c 500` (`makeSpringAnimationImpl`), iOS 26 smooth
  `m 1, k 555.027, c 47.118` (`make26SpringAnimationImpl`), bounce
  `m 5, k 900, c 88` (`makeSpringBounceAnimationImpl`, where 88 is the default
  `damping` argument in `CALayer.animateSpring`). Damping ratios: 4.5644
  (heavily overdamped), 1.0000 (exactly critical — Apple tuned it that way),
  0.6559 (6.5 % overshoot). Two consequences:
  - the raw `mass`/`stiffness`/`damping` are exported as bare-number tokens,
    because `motion`/framer-motion takes those three in the same units as
    `CASpringAnimation`. The JS layer must read the tokens, not retype numbers.
  - the CSS easings are **generated** from the analytic step response of each
    spring, not approximated with a bezier. A bezier cannot express the bounce
    curve at all (it is not monotonic) and misrepresents the long tail of the
    standard spring. Script below; regenerate rather than hand-edit.

  On the standard spring's 3419 ms settling time: Telegram never plays it for
  3.4 s. `CALayer.makeAnimation` sets `animation.duration = settlingDuration`
  and then `animation.speed = duration / requested`, i.e. it compresses the
  whole curve into the requested duration (typically 0.3–0.5 s). So the
  `linear()` shape is the correct normalised progress and the duration token
  supplies the time — which is exactly how a CSS `transition` works.

- 2026-09-30 **The cubic-beziers in the token set are Telegram's own, not
  spring approximations.** `--tg-ease-standard` is tweb's
  `--transition-standard-easing`, `--tg-ease-decelerate` is Android's
  `EASE_OUT_QUINT`, `--tg-ease-overshoot` is Android's `EASE_OUT_BACK` (the
  same curve tweb uses for `--btn-corner-transition`), and so on. They are in
  the vocabulary because Telegram ships them, and the preview page puts
  `--tg-ease-spring` and `--tg-ease-standard` on adjacent tracks so the
  difference is visible rather than asserted.

- 2026-09-30 **Night is a designed theme, not an inverted day.** Four things
  differ by rule, not by value: the accent changes hue (blue → violet); the
  outgoing bubble changes *derivation* (day: a green independent of the accent;
  night: the accent itself — `messageLightenAlpha` is 0.12 on day and 1 on
  night); the divider is darker than the surface instead of lighter; and the
  link colour resolves to the accent instead of to a separate AA-safe blue.
  tdesktop's navy Night (`#17212b` / `#182533` / `#2b5278`) is a *different*
  Telegram theme and was deliberately not blended in — its values are parked in
  `primitive.css` as `--tg-raw-navy-*` so TG-507 can ship it as a third
  built-in without re-doing this research.

- 2026-09-30 **An accent override sets the accent block and the outgoing bubble
  and nothing else.** Badges, the selected chat row, the focus ring, avatars and
  in-bubble links all read `var(--tg-accent)` from the theme file, so they
  follow for free. Each accent file is ~14 declarations and restyles the whole
  application; if a future accent file needs to name anything else, the theme
  file is wrong, not the accent file.

- 2026-09-30 **Accent-derived bubbles use Telegram's formulas, not ours.** Day:
  `mix(accent, surface, 0.12)`, from tweb's `themeController`. Night: iOS's
  two-stop derivation
  `bottom = accent.withMultiplied(1.019, 0.731, 0.59)`,
  `top = bottom.withMultiplied(0.966, 0.61, 0.98)` (HSV channel multiplication,
  `DefaultDarkTintedPresentationTheme.swift:88-91`). The night result is muted
  on purpose: the factory violet works as a flat bubble only because it was
  chosen to, and a saturated cyan rectangle is unreadable. All values were
  computed with the script below and baked as literals rather than derived at
  runtime, so the files work with no build step and in any browser.

- 2026-09-30 **Wallpaper is a third independent axis, decoupled from the
  accent.** Telegram bundles a wallpaper *with* each accent preset. Coupling
  them in CSS would make the accent selector (specificity 0,2,0) beat the
  wallpaper selector (0,1,0) and silently break wallpaper switching. The token
  layer keeps `theme × accent × wallpaper` orthogonal and TG-507 may re-couple
  them in application code, where it belongs. The preset colour data is
  preserved either way: light presets are iOS `dayClassicColorPresets`, dark
  presets are `PresentationThemeBaseColor.colorWallpaper`, and the factory
  wallpaper is `defaultBuiltinWallpaperGradientColors`
  (`#dbddbb #6ba587 #d5d88d #88b884`, intensity 50).

- 2026-09-30 **No `prefers-color-scheme` rule in the token layer.** Expressing
  it in CSS would mean duplicating the entire night block into a media query
  (there is no way to reuse a declaration block in plain CSS). Choosing a theme
  from the OS preference is application policy: TG-507 sets `data-tg-theme`
  from `matchMedia`. One line there beats 120 duplicated lines here.

- 2026-09-30 **`prefers-reduced-motion` degrades rather than disables.** All
  movement durations collapse to 1 ms (not 0 ms, so `transitionend` still fires
  and state machines waiting on it do not stall), spring easings become
  `linear`, the ripple stops travelling but still flashes, and the JS spring
  parameters are replaced with a stiff critically damped spring so
  `motion`-driven animation degrades too. `--tg-duration-fade` deliberately
  survives: things still cross-fade.

- 2026-09-30 **Motion lives in `motion.css`, not in `primitive.css`.** Same
  layer, same `--tg-raw-` rule. Split because the repository's 350-line `.css`
  gate would otherwise leave motion — the token group most likely to grow — with
  two lines of headroom.

- 2026-09-30 **Emoji fonts moved to the end of the font stack.** tweb lists
  `apple color emoji` third in `--font-regular`. Copying that verbatim made the
  space glyph resolve from the emoji font and every word gap in the preview
  page doubled. Deliberate deviation from the reference; the emoji families are
  last.

### Regeneration script for the spring easings

Paste into a file and run with python3. It prints the three `linear()` values in
`motion.css`. `warp` densifies the sampling where the curve is steep; the
printed `maxErr` is the worst deviation of the piecewise-linear approximation
from the true solution (currently ≤ 0.004 for all three).

```python
import math
def spring(m, k, c):
    w0 = math.sqrt(k / m); z = c / (2 * math.sqrt(k * m))
    if abs(z - 1) < 1e-9:
        f = lambda t: 1 - math.exp(-w0 * t) * (1 + w0 * t)
    elif z < 1:
        wd = w0 * math.sqrt(1 - z * z)
        f = lambda t: 1 - math.exp(-z * w0 * t) * (
            math.cos(wd * t) + (z * w0 / wd) * math.sin(wd * t))
    else:
        r1 = -z * w0 + w0 * math.sqrt(z * z - 1)
        r2 = -z * w0 - w0 * math.sqrt(z * z - 1)
        f = lambda t: 1 - (r2 * math.exp(r1 * t) - r1 * math.exp(r2 * t)) / (r2 - r1)
    T, t = 0.0, 0.0
    while t < 20:                       # settling time at the 0.001 threshold
        if abs(f(t) - 1) >= 0.001: T = t
        t += 0.0005
    return z, w0, T + 0.0005, f

for name, (m, k, c), n, warp in [
        ("standard", (3, 1000, 500), 22, 2.6),        # makeSpringAnimationImpl
        ("smooth",   (1, 555.027, 47.118), 20, 1.7),  # make26SpringAnimationImpl
        ("bounce",   (5, 900, 88), 34, 1.15)]:        # makeSpringBounceAnimationImpl
    z, w0, T, f = spring(m, k, c)
    stops = [((i / (n - 1)) ** warp, f(((i / (n - 1)) ** warp) * T)) for i in range(n)]
    stops[0], stops[-1] = (0.0, 0.0), (1.0, 1.0)
    body = ", ".join(f"{round(v, 4):g} {round(x * 100, 2):g}%" for x, v in stops)
    print(f"/* {name} m={m} k={k} c={c} zeta={z:.4f} w0={w0:.2f} settling={T*1000:.0f}ms */")
    print(f"linear({body})\n")
```

The accent derivations (`mix(accent, white, 0.12)`, the HSV `withMultiplied`
pair, HSL lightness −8/−14) were computed with a sibling script that is not
worth preserving: every result is baked into the accent files with the formula
named in a comment beside it, so any value can be re-derived in isolation.

- **The Echo Gate brand is gone from the interface.** Jade/coral/sun are not in
  the token set at all. This follows from "visual parity with Telegram" but it
  contradicts `design/README.md` §3, which is still the live brand document.
  Somebody with product authority should confirm this before TG-010 builds 19
  components on a blue/violet system. This is the highest-value thing in this
  section.
- **Three of Telegram's own colours fail WCAG AA and were kept anyway.** White
  on the day accent `#3390ec` is 3.31:1; `--tg-bubble-out-meta` `#5CA853` on the
  outgoing bubble is 2.75:1; `--tg-online` `#70b768` on white is 2.42:1. All are
  ≥ 3:1, which is AA for large text and non-text UI, and all are what Telegram
  ships. `design/README.md` §9 asks for 4.5:1 on body text. Where a token is
  used for body text we deviate deliberately — `--tg-text-link` is `#00488f`
  (9.04:1), which is Telegram's own answer to the same problem, and
  `--tg-text-success` is `#3e7138` (5.79:1) rather than the 2.42:1 green. The
  cyan accent is the worst case at 2.11:1 for white-on-accent and is flagged in
  `themes/accents/cyan.css`. A reviewer who needs strict AA should treat the
  accent-contrast pairs as the place to intervene, not the whole system.
- **Values marked `[ours]` are the ones to distrust**, and they are marked
  everywhere they occur. The complete list: the `−14` HSL step for
  `--tg-accent-active` (the `−8` hover step is tweb's, the `−14` is not from any
  source); night `--tg-surface-active` at 14 % white (the 8 % hover step is
  tweb's `$hover-alpha`); `--tg-duration-press: 100ms` (tweb puts no transition
  on hover at all, so there was nothing to copy); `--tg-bubble-shadow` on day
  (tweb draws no bubble shadow, Telegram Android does — set it to `none` to
  match the web client exactly); `--tg-overlay-strong`;
  `--tg-raw-size-bubble-max: 480px` (tweb clamps to a runtime `--chat-width`, so
  480px is the value at the default column width, not a constant Telegram
  stores); `--tg-raw-letter-spacing: 0` (carried from `design/README.md` §8);
  all 14 wallpaper preset *names*, though every preset's colours are verbatim.
- **Unanchored steps in the four colour ramps are interpolation, not Telegram.**
  Only the 500 step of each ramp plus the explicitly named entries
  (`--tg-raw-green-bubble-day`, `--tg-raw-blue-link-day`, the neutrals, the nine
  accent base colours, the four navy values) are real Telegram values. The rest
  exist so components have a ramp; nothing currently consumes them.
- **The night theme is one of three plausible Telegram darks.** tweb's neutral
  grey + violet was chosen; tdesktop's navy and iOS's pure-black-with-white-
  accent were not. If a reviewer's screenshot is from Telegram Desktop, the
  night pane will legitimately not match, and `--tg-raw-navy-*` is the fix.
- **The four-point wallpaper is an approximation.** Telegram sums four colour
  points with a 1/d⁴ weight on a canvas and animates the point ring on every
  sent message; the CSS uses the fourth colour as a base plus three radial
  gradients at the rest positions from `gradientRenderer.ts`. Correct at the
  anchors, visibly different in the transition zones, and not animated.
- **The service-plate colour is wallpaper-derived and is currently a literal.**
  `--tg-service-bg` / `--tg-message-highlight` carry tweb's value for the
  default wallpaper in both themes (tweb declares it on `.chat`, not per theme,
  which is why it is the same in day and night). It will look wrong on a dark
  wallpaper until TG-507 recomputes it from the active wallpaper.
- **`linear()` support.** The generated spring easings need Chrome 113+,
  Safari 17.2+ or Firefox 112+. Below that the easing is ignored and the
  transition falls back to linear timing, which is a degradation rather than a
  break. Relative-colour syntax and `color-mix()` were deliberately avoided so
  nothing else in the token layer has a support floor.
