## Frozen interface

Everything is exported from `packages/web/src/features/mediaViewer/index.ts`.

```ts
// Mount once at the app root. Renders nothing until opened; the open viewer is a lazy chunk.
<MediaViewer actions?={MediaViewerActions} createFetcher?={(chatId) => FetchMediaPage} />

// Open / close. Bind the bubble: actions.onOpenMedia = (id) => openMediaViewer({ chatId, attachmentId: id })
openMediaViewer({ chatId: string, attachmentId: string, sourceRect?: Rect | null }): void
closeMediaViewer(): void            // immediate, no exit animation (e.g. the Chat was left)
mediaViewerStore                    // zustand vanilla store { request, open, close }

interface MediaViewerActions {      // every member optional; absent → button hidden
  onDownload?(item: MediaItem): void                       // default: <a href download>
  onForward?(item: MediaItem): void                        // viewer stays open (z-index below dialogs)
  onDelete?(item: MediaItem): Promise<boolean> | boolean   // true → item dropped, move to neighbour / close
  canDelete?(item: MediaItem): boolean                     // default true when onDelete is set
}

interface MediaItem { attachmentId, messageId, kind: 'image' | 'video', url, fileName, mimeType,
  sizeBytes, isSensitive, sender, senderId, createdAt, caption: string | null }
type FetchMediaPage = (before: string | null) => Promise<{ items: MediaItem[]; nextBefore: string | null; oldestAt: string | null }>
```

Contract details the integrator relies on:

- `sourceRect` is optional. Without it the viewer finds the bubble thumbnail itself: TG-103
  renders `.tg-bubble__media > img|video[src=download_url]`, and `download_url` is unique per
  attachment. No bubble change is needed. A thumbnail that is not on screen → fade instead
  of flight.
- The seed is read once at open from `messageStore.timelines[chatId]` (`@tg/core`).
- The default fetcher calls `GET /api/chats/:id/files?kind=all&limit=100` with the session
  token (`authStore`). Password-protected chats: pass `createFetcher` with
  `createChatMediaFetcher(chatId, { client, token, password })`.
- Stacking: `.tg-mv` is `z-index: 1050` — above `Popover` (1000), below `Dialog`/`Modal`
  (1100), so a forward picker or delete confirmation opened from the viewer shows on top.

## Decisions

- 2026-10-01 Page media through the existing `GET /api/chats/:id/files` (keyset, newest first,
  cursor = message id) with `kind=all` filtered client-side, rather than adding a server
  `kind=media`, because the card's allowed paths are frontend-only and the listing already
  authorises at read time. Cost: a page can contain zero media and still advance; the pager
  handles that by keeping the raw-row cursor (`nextBefore`) separate from the items.
- 2026-10-01 Open instantly on the seed (loaded timeline), then sync the newest end from the
  head until the pages reach the seed (`oldestAt <= seedNewest.createdAt`), because the
  listing has no "after" direction: without the sync, media newer than a deep-linked window
  would be silently skipped. Bounded at 8 pages; past that the seed alone is kept (no gap
  shown). Recorded under Residual risk.
- 2026-10-01 Timestamps compared with `Date.parse`, not strings, because chrono's RFC 3339
  output trims fractional seconds to 0/3/6/9 digits, which breaks lexical order.
- 2026-10-01 One animation primitive (`viewerMotion.runProgress`: 0→1 over TG-009's `smooth`
  spring, or a `--tg-duration-fade` linear tween under reduced motion) instead of per-element
  `motion` components, so every moving part (flight, slide, zoom settle) degrades in one
  place. `smooth` (critically damped, ~390 ms) rather than `standard`, because `standard`
  settles in 3.4 s when run at its real time constant (see `motion.css`).
- 2026-10-01 Shared element = a separate "flight" element carrying a snapshot (the image URL,
  or a canvas still of a video frame) that morphs size + corner radii between thumbnail and
  stage; the stage is `visibility: hidden` until the stage image has `decode()`d. React state
  that must change in the same frame as the imperative style writes goes through `flushSync`.
  This is what guarantees no blank/white frame (verified per frame, see Verification).
- 2026-10-01 Fitted without upscaling (CSS `max-*: 100%` for images; the video host uses
  container-query units with the same rule) so the flight target computed in JS equals the
  CSS layout exactly — no jump at the end of the flight.
- 2026-10-01 Zoom/pan transform written directly to the element (no React render per pointer
  move); pointer capture only once a drag is recognised, because capturing on press
  retargets the tap's `click` to the stage and swallows plyr's click-to-play.
- 2026-10-01 plyr sprite inlined from the installed package (`?raw` import of
  `node_modules/plyr/dist/plyr.svg`) with `loadSprite: false`, because the server CSP
  (`connect-src 'self'`) blocks plyr's default XHR to cdn.plyr.io and the controls would render
  blank (the old Vue client has this bug). The package does not export the SVG, hence the
  relative path.
- 2026-10-01 `motion` + the surface are a lazy chunk (`React.lazy`), preloaded on the first
  `pointerdown` on any `.tg-bubble__media`; plyr is a second lazy chunk loaded only when a video
  becomes current. Keeps the entry bundle +1 KB.
- 2026-10-01 Current item addressed by attachment id (a ref, not an index), so prepending an
  older page never moves the view and two key presses faster than a render both count.
- 2026-10-01 Reused TG-103 internals by import (read-only): `attachmentKind` (SVG stays a file)
  and `MessageText` (caption linkify), instead of copies that would drift.

## Residual risk

- Deep-linked windows (seed far from the head, > 8 pages of 100 rows): the viewer keeps the
  seed only, so media newer than the loaded window is not reachable from the viewer until the
  chat is reopened at the bottom. A server `after` cursor on `/files` would remove this.
- Media from `/files` carries no caption (the listing has no `content`); only seeded items show
  captions.
- Live changes while open (a new photo arrives, another member recalls one) are not merged
  into an open viewer; a recalled item disappears on the next open.
- The fixture page's optional `sample.webm` is generated locally and not committed.
- plyr's sprite path reaches into `packages/web/node_modules/plyr/dist/plyr.svg`; a plyr major
  upgrade that moves it breaks the build loudly (not silently).
