## Decisions

- 2026-10-01 An album is N ordinary messages sharing `grouped_id`, not a new row kind — every
  read path (history, search, unread, previews, reactions, recall, media viewer) keeps working
  per item. (Original owner.)
- 2026-10-01 The list collapses a consecutive same-sender run of one `grouped_id` into ONE row
  inside `messageListState.visibleWindow` (`features/album/albumCollapse.ts`), instead of
  zero-height sibling rows: Virtuoso misbehaves on zero-sized items and the anchor math would
  have to learn about them. The row keeps the FIRST item's id/key (stable while the rest of the
  album streams in) and the LAST item's timestamp; `rowIndexOf` matches any member so jumps land
  on the album. Items are attached through a WeakMap (`albumItemsOf`), so no wire/core type grows
  a client-only field; representatives are cached per `grouped_id` while their items are
  identical objects, preserving TG-101's identity-based layout cache.
- 2026-10-01 Mosaic = a faithful port of Telegram Desktop's `LayoutMediaGroup` as a pure core
  function (`albumLayout.ts` + `albumLayoutRows.ts`), not an equal grid. Attachments carry no
  dimensions on the wire, so tiles start square and re-lay out when each image/video reports its
  natural size (the list measures rows, as for any loading image). A server-side dimension field
  would remove the reflow — follow-up candidate.
- 2026-10-01 Album row actions: delete / forward / select act on every item; reply, react, pin
  and caption edit address the first item (which carries the caption). Forwarding all items keeps
  them an album in the target (`ForwardPlan`).
- 2026-10-01 Composer: a batch of 2–10 photos/videos (not «以文件形式发送», nothing sent yet)
  uploads every file's chunks first, then one `POST /albums`; any failure marks the whole album
  failed and «重试» resumes the sessions by fingerprint. Other batches keep one message per file.
  `uploadClient.uploadAttachment` was split into `uploadChunks` + complete for this.

## Residual risk

- The mosaic reflows once per tile as images load (no dimensions on the wire).
- `albumCollapse` keys runs on `grouped_id` + sender adjacency; if another message were ever
  inserted between album items (it cannot today — one transaction, 1 µs-spaced timestamps), the
  album would render as two rows rather than breaking.
