## Frozen interface

- `PUT /api/chats/{channel}/discussion {chat_id: uuid|null}` → `{channel_id, linked_chat_id}`;
  `chat.info` in the channel and (to link) in the group; 400 not a group/supergroup, 409 the
  group already serves another channel. Both chats get `chat_updated`.
- `GET /api/chats/{channel}/posts/{post}/comments` → `CommentThread {discussion_chat_id,
  discussion_message_id, count, can_comment, messages[]}` (oldest first, ≤ 500). Any reader of
  the channel may read; 404 when the post has no thread or is recalled.
- `POST /api/chats/{channel}/posts/{post}/comments {content, reply_to?, client_message_id?}` →
  201 `StoredMessage` (a reply in the discussion group). 403 unless the caller may send in the
  group; slow mode via `resolve_post_topic`; `reply_to` must be inside the thread (400).
- `StoredMessage.comments` / broadcast frame `comments`: a post's live comment count, present
  only on posts that have a thread.
- Core `createDiscussionApi` (link / thread / comment / join).

## Decisions

- **The copy is a database trigger**, like TG-202's `post_author`: every send path (text, media,
  stickers, forwards, scheduled, albums) inserts messages itself. AFTER INSERT on a channel with
  a `linked_chat_id` writes a `channel_discussion_threads` row and the copy (sender = the channel,
  no account; shown as forwarded from it). Kinds that live on the row copy as such (text,
  attachment, sticker); a poll/voice note arrives as its text/attachment. The live poller
  delivers the copy to the group like any new row; `invalidate_message_cache` on a channel also
  invalidates its linked group's Redis history.
- **Post deletion is defined:** recalling a post recalls its copy (trigger); the comments stay in
  the group as replies to a recalled message, and the channel's thread endpoint answers 404. A
  hard delete (auto-delete timer) recalls the copy before the mapping cascades. Editing a post
  edits its copy.
- **Unlinking** clears both sides; existing threads stay mapped and readable from the channel; new
  posts get no thread (no `comments` field).
- Counts include replies to replies (recursive CTE restricted to the group), excluding recalled.
- Reading comments needs only the channel (Telegram); writing needs the group: the panel offers
  «加入讨论组以评论» (`POST /join-requests`, immediate for open groups).
- Comment counts on the channel are refreshed on load and when the sheet opens, not pushed live
  per comment (a per-comment frame to every subscriber is the fan-out TG-202 avoids).
