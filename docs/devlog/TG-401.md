## Frozen interface

### Storage (migration `20270101000001_add_voice_notes`, SQLite + PostgreSQL)

- A voice message is an attachment message with `messages.media_kind = 'voice'` (TG-302's
  column) plus one `voice_notes` row.
- `voice_notes(message_id PK → messages ON DELETE CASCADE, duration_ms INTEGER > 0,
  waveform BLOB/BYTEA (100 × 5-bit, packed little-endian, 63 bytes), duration_source
  'container'|'client', created_at)`.
- `voice_listens(message_id → voice_notes ON DELETE CASCADE, user_id → users, listened_at)`,
  PK `(message_id, user_id)`. The sender never has a row for their own message.

### Wire

- `VoiceNote { duration_ms: u32, waveform: u8[100] (0..=31), listened: bool }` — Rust
  `src/attachments/voice/model.rs`, TS `packages/core/src/types/message.ts`.
- `StoredMessage.voice?` / `broadcast.voice?` — omitted unless the message is a voice message
  whose attachment the viewer can see (a recalled one loses both). `media_kind: "voice"` rides
  along (TG-302 field).
- `listened` is **per viewer**: for the sender, "some other member played it"; for anyone
  else, "I played it". Chat-wide `broadcast` frames of a new message carry `false`.
- `voice_listened { message_id, user_id, sender_id }` — emitted once per (message, listener),
  on the first listen, and delivered **only** to `user_id`'s and `sender_id`'s own
  connections (`frame_visible_to`). A bystander never learns who listened.

### HTTP (`src/attachments/voice/handlers.rs`, OpenAPI-registered)

| Method | Path | Body | Answers |
| --- | --- | --- | --- |
| POST | `/api/chats/:id/voice` | multipart: `file`, `waveform` ("n,n,…" 100 ints 0–31), `duration_ms` (recorder measurement), `reply_to?` | 201 `StoredMessage` with `voice` |
| POST | `/api/messages/:message_id/voice/listened` | — | 204 (idempotent; sender's own = no-op) |

Errors (JSON `{error}`): 400 `invalid_waveform` / `invalid_duration` / `missing_duration` /
`missing_file`; 401; 403 `forbidden` (no send permission) or `voice_messages_restricted`
(TG-505 rule of the private-chat peer); 404 (no chat / not a member / not a voice message —
never distinguished); 413 `too_large` (24 MiB cap, or the deployment's upload limit if lower);
415 `unsupported_audio` (not Ogg, WebM or MP4 by magic bytes).

### Client (`@tg/core`)

- `packages/core/src/api/voice.ts`: `sendVoiceMessage(fetchImpl, {chatId, token, audio, fileName,
  durationMs, waveform, replyTo?, signal?}) → StoredMessage` (multipart; throws `ApiError` with
  the server's `error` code), `markVoiceListened(client, token, messageId)`,
  `VOICE_WAVEFORM_SAMPLES`/`VOICE_WAVEFORM_MAX`, `VOICE_RESTRICTED`.
- Types: `VoiceNote`; `StoredMessage.voice?`/`media_kind?`; `BroadcastFrame.voice?`/`media_kind?`;
  `VoiceListenedFrame` in `ServerFrame`; `frameCodec` knows `voice_listened`;
  `storedMessageToBroadcast` carries `voice`/`media_kind`.
- `packages/web/src/features/voice` exports `VoiceRecordButton` (the composer's mic),
  `VoiceContent`/`VoiceBody` (bubble), `applyVoiceListenedFrame`/`voiceStore`; `register.ts`
  registers kind `voice` at priority 40 (match: `message.voice && message.attachment`).

The stored MIME type and file name come from the sniffed container (`audio/webm`,
`audio/ogg`, `audio/mp4`; `voice.webm|ogg|m4a`), never from the client.

## Decisions

- 2026-10-01 **Waveform computed by the recorder, validated and stored by the server** — not
  decoded server-side. Decoding Opus/AAC in pure Rust needs a new codec crate (symphonia-class,
  plus libopus bindings for Opus), which the brief rules out. The card's real concern is "a
  client must not decode a whole file to draw a waveform on playback"; that is met because the
  waveform is computed once, from the live PCM the recorder already has (AnalyserNode), and
  every playback reads the stored 100 samples. The server enforces shape (exactly 100 samples,
  each 0–31) and stores Telegram's packed 5-bit form. Trade-off: a malicious client can store
  a waveform that does not match its audio (cosmetic only — it cannot affect other data).
- 2026-10-01 **Duration from container framing, recorder value only as fallback.** Ogg: last
  granule − pre-skip @48 kHz; WebM: `Info/Duration`, else newest Cluster+Block timestamp
  (MediaRecorder never writes Duration); MP4: `mvhd`, else `mdhd`, else Σ `trun` sample
  durations (fragmented recordings). `voice_notes.duration_source` records which was used.
  WebM's block-timestamp duration is short by at most one frame (20–60 ms): accepted.
- 2026-10-01 **Own endpoint `POST /api/chats/:id/voice` instead of new fields on the generic
  attachment upload.** The generic handler lives in `src/attachments/handlers.rs` (not this
  card's path) and knows nothing about waveforms; the voice endpoint reuses the same
  pipeline pieces (`attachment_store().begin/hash_staged/commit`, content-hash locks and dedup,
  the work-queue upload permit) and writes attachment + message + `voice_notes` in one
  transaction, exactly like TG-302's sticker send. Voice notes are small (≤ 24 MiB), so the
  single-shot multipart path is enough; resumable sessions are not needed.
- 2026-10-01 **Listened frame goes to the listener and the sender only.** Telegram never shows
  a group who listened; broadcasting chat-wide would leak it. `frame_visible_to` already
  filters `draft_updated` the same way.
- 2026-10-01 **Forwarding keeps a voice message a voice message** (Telegram semantics):
  `forward_store.rs` copies the `voice_notes` row and sets `media_kind` in the same
  transaction. Listened state is not copied.

- 2026-10-01 **`Permissions-Policy: microphone=(self)`** (was `microphone=()`, which made every
  `getUserMedia` fail with "Permissions policy violation" — found by the E2E). One token in
  `src/security/headers.rs`; `camera=()` stays for TG-402 to decide, `geolocation=()` for TG-407.
  Pinned by `voice_messages_test::the_page_may_open_the_microphone_but_not_the_camera_or_location`.
- 2026-10-01 **Fragmented MP4 duration = last fragment's `tfdt` + its `trun`s**, not Σ`trun`
  and not `mvhd`: Chromium's MP4 recorder writes `mvhd` = 6 ms and a short last-sample duration
  per fragment (Σ`trun` = 1.647 s vs ffprobe 1.881 s). Pinned by real fixtures in
  `tests/fixtures/voice/` (`voice_probe_fixture_test`).
- 2026-10-01 **Waveform buckets by time, sample-and-hold.** Levels are timestamped (40 ms
  timer); a throttled background tab still yields an aligned waveform (test
  `waveform.test.ts` "throttled"). Normalised to the loudest peak, like Telegram.
- 2026-10-01 **Gesture: a tap (< 300 ms) or Enter/Space = hands-free (locked) recording**;
  hold+release sends; slide left 120 px cancels; slide up 80 px locks; Escape cancels;
  recordings < 700 ms are dropped. Desktop Telegram behaves the same way for a click, and it
  gives keyboard users a way to record at all.
- 2026-10-01 **Own `ChatActionSender` in the recorder** (TG-107 `createChatActionSender`, over the
  composer's `sendFrame`): `recording_voice` → `uploading_voice` → `cancel`. The composer's
  typing sender is not exposed by `ComposerController`, and the two never overlap in time.
- 2026-10-01 **One app-wide player** (`appVoicePlayer`, one `Audio` element): starting a voice
  message stops the previous one; on `ended` the next voice message in the open timeline
  plays; speed 1×/1.5×/2× (pitch preserved) persists in storage (`tg.voice.rate.v1`). Progress
  is read from the element on animation frames; the duration always comes from the server
  (MediaRecorder WebM reports `Infinity`). Seeking such a WebM works in Chromium (E2E step 8).
- 2026-10-01 **Listened reporting**: first play of someone else's unlistened voice message →
  local mark at once + `POST …/voice/listened` once per page lifetime (retried on failure).
- 2026-10-01 **`voice_listened` wired in `features/chat/chatSession.ts`** (one `socket.on` line)
  — outside this card (TG-110 owns features/chat), but that file is the single frame fan-out
  (its header says M1+ tasks extend it rather than open a second subscription).

## Residual risk

1. **Chat-list preview** (`features/chatList/chatPreview.ts`, TG-502) guesses media from the file
   extension: a voice message shows «视频» (`voice.webm`) or «音频» (`voice.m4a`); only
   `voice.ogg` reads «语音消息». Proper fix: the conversation summary carries `media_kind` and
   the preview prefers it. Not done here (other owner's path, and it touches the list summary).
2. Forwarding a voice message into a private chat does not consult the recipient's TG-505
   `voice_messages` rule (only direct sends do). Telegram refuses such forwards.
3. The waveform is client-computed: a modified client can store a waveform unrelated to its
   audio (cosmetic; shape and range are enforced).
4. Real Safari/Firefox were not run: the MP4 branch was exercised in Chromium by stubbing
   `isTypeSupported`, and the Ogg path only by an ffmpeg fixture.
5. Voice upload is single-shot multipart (no resume), capped at 24 MiB (≈ 1 h of Opus).
6. WebM durations are the last block's start (≤ one frame short, 20–60 ms).
7. Migration version `20270101000001` sorts before already-applied `20270101000006`/`2027020…`;
   sqlx applies it out of order (tested on both adapters: `*_out_of_order_upgrade_*`).
