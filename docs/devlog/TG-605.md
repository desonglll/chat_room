## What it proves

`hosts/node/smoke.ts` lives outside `packages/core` and is a complete non-DOM host: it injects
Node implementations of the three platform seams core defines (`CoreStorage` — a Map;
`CoreSocketFactory` — Node 24's built-in WHATWG `WebSocket` adapted to core's handler-property
shape; `CoreClock` — `Date.now`/`setTimeout`) and the `fetch` the API client takes, then:
sign up → list chats → create a chat → open its realtime socket through `createChatSocket` →
send a message → receive its `broadcast` → read it back with `listChatMessages`.

## Verification

- `tests/core_node_host_test.rs` (runs in the normal cargo suite): serves the app, typechecks the
  host with **no DOM lib** (`hosts/node/tsconfig.json`, `lib: ES2023`), bundles it with
  `bun build --target=node`, asserts the bundle never touches `document.`/`window.`, and runs it
  with plain `node` (no polyfill, no jsdom). It also refuses to start if a DOM global exists.
  Skips visibly when `node` or `bun` is not installed.
- Result: 1/1 on Node v24.18.0.

## Decisions

- The host imports core by source path and Bun bundles it (core uses extensionless ESM
  specifiers, which Node's loader does not resolve; bundling is how any real host would ship it).

## Residual risk

- Node < 22 has no global `WebSocket`; such a host would inject a library socket instead (the
  seam is exactly for that).
