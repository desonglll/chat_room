### Also exported

`VisuallyHidden` (TG-002's, unchanged) and the JS-animation bridge:
`readSpring(name: 'standard' | 'smooth' | 'bounce', from?: Element | null): SpringTokens | null`
and `usePrefersReducedMotion(): boolean`. `readSpring` returns `null` rather than fallback numbers
when the token layer is not loaded — see Decisions.

### Class-name contract

Every component's root carries a `tg-<component>` class and modifiers in BEM-ish form
(`tg-button--filled`, `tg-menu__item`). Component-internal CSS variables are named `--tg-ui-*` so
they can never be mistaken for a TG-009 token. Applications may target these classes, but they are
**not** frozen: the frozen surface is the props.

## Decisions

- 2026-09-30 **Plain CSS consuming the variables, not Tailwind `@theme`.** Tailwind 4 is in the
  stack table but wiring it here would (a) add `@tailwindcss/vite` as a build step between
  `packages/ui` and its consumers, which TG-002 deliberately avoided by consuming packages as
  TypeScript source, and (b) break the documentation page, which must run with no build
  configuration the way TG-009's `preview.html` does. It would also weaken the discipline test:
  utility class names in JSX are harder to scan than `background-color: var(--tg-accent)`.
  Tailwind stays available to `packages/web` for layout; `@tg/ui` does not need it.

- 2026-09-30 **All motion is CSS; the package does not depend on `motion`/framer-motion.** TG-009
  put the `prefers-reduced-motion` degradation in `semantic.css`, so anything driven by
  `--tg-transition-*` or `--tg-duration-*` degrades for free and cannot drift from the token
  layer. A JS animation library would mean re-implementing that degradation per component, plus a
  dependency with one consumer. The springs are still exported for M1 through `readSpring`, which
  reads the tokens rather than retyping the numbers.

- 2026-09-30 **`readSpring` returns `null` when the token layer is absent, instead of falling back
  to literals.** Baking `mass: 3, stiffness: 1000, damping: 500` in here would create a second
  source of truth for numbers TG-009 froze, and it would drift silently. A caller that gets `null`
  knows the stylesheet is missing.

- 2026-09-30 **One stylesheet entry (`src/styles.css`) rather than `import './Button.css'` inside
  each component.** Packages are consumed as source, so a CSS import inside a `.tsx` forces every
  consumer — including `bun test` and the docs page — to have a CSS loader. One entry is also one
  place to audit, which is what the discipline test scans.

- 2026-09-30 **Ripple is Telegram's, and the difference from Material is three specific things**,
  all encoded in `internal/rippleGeometry.ts` and asserted in `rippleGeometry.test.ts`:
  1. the circle is centred on the pointer and **stays there**. Material's ripple translates the
     circle from the pointer towards the element centre while it expands;
  2. the diameter is `max(width, height)` of the host, **not** the diagonal, so on a wide control
     the wave is not guaranteed to reach the far corner. Material sizes for guaranteed coverage.
     The test asserts the shortfall rather than "fixing" it;
  3. it runs `--tg-ripple-scale-start` → `--tg-ripple-scale-end` (0 → 2) over
     `--tg-ripple-duration` (700ms) to completion, roughly three times Material's, and is not cut
     short on pointer release.
  Measured in a real browser: host 1174×80, pointer at (12, 12) → `left: -575`, `top: -575`,
  `diameter: 1174`. That is `max(w, h)` and `pointer − d/2`, i.e. exactly (1) and (2).

- 2026-09-30 **Keyboard activation spawns a ripple from the host centre.** Without it a keyboard
  user gets no press feedback at all. `hostCentre()` exists for that one case.

- 2026-09-30 **`Popover` has a three-valued `focus` mode, not a `trapFocus` boolean.** The first
  version had the boolean and it was wrong in both directions: `Menu` needs focus MOVED in but Tab
  left alone (the ARIA menu pattern makes Tab dismiss a menu), and `Tooltip` must not touch focus
  at all — moving focus into a tooltip blurs its own trigger, which fires `onBlur` and closes it.
  That bug was caught by driving a real browser, not by a unit test, and is why the mode is now
  `'trap' | 'move' | 'none'`.

- 2026-09-30 **Focus restoration is its own hook, declared after the trap, and captures the
  element during render.** Three orderings had to be right and each was wrong once:
  - restoration cannot live inside `useFocusTrap`, or every untrapped overlay silently loses it;
  - the previous element must be captured **during render**, because by the time effects run the
    trap has already moved focus into the overlay — capturing in an effect stores a control that
    is about to be unmounted, and nothing is restored;
  - `useRestoreFocus` must be declared **after** `useFocusTrap`, because cleanups run in
    declaration order and the trap's `focusin` recovery listener would otherwise see focus leaving
    and immediately drag it back.

- 2026-09-30 **`usePresence` flips `present` during render, not in an effect.** The exit-animation
  hook originally set `present` in an effect. That made the overlay surface mount one commit after
  `open` became true, so `useFocusTrap` and `useAnchoredPosition` ran against a ref that was still
  `null` and — because their dependencies did not change afterwards — never ran again. Result: no
  focus trap and no Escape on any dialog. Same class of bug in `Portal`, which resolved
  `document.body` in an effect; it now resolves during the first client render.

- 2026-09-30 **Focus entry uses the same `nextTabStop` rule as cycling.** `collectFocusable`
  includes the container itself (it carries `tabIndex={-1}`), so the naive "first focusable
  descendant" landed focus on the panel div and the first arrow key went nowhere. Entry now picks
  the first **tabbable** element, which is the container only when there is nothing inside.

- 2026-09-30 **Overlay dismissal is layer aware** (`internal/layerStack.ts`, a module-level
  stack). Escape closes only the topmost layer, so a `Menu` opened inside a `Modal` takes the
  first Escape and the `Modal` takes the second. The stack is deliberately not React state:
  ordering has to be readable synchronously from an event handler, before any render.

- 2026-09-30 **Outside-dismissal listens to `pointerdown`, not `click`.** By the time a `click`
  completes, the user may already have pressed a control on the layer underneath.

- 2026-09-30 **`Menu` is data-driven (`items: MenuItem[]`), not `Menu.Item` children.** A uniform
  row descriptor is what lets one component own roving focus, typeahead and the disabled-row skip
  without walking an arbitrary child tree — and every Telegram menu row has exactly this shape.
  Submenus are deliberately out: nothing in M0–M1 needs one, and a submenu changes the keyboard
  model (ArrowRight opens, ArrowLeft closes). Add it when a consumer appears.

- 2026-09-30 **`MenuList`'s roving tab stop is computed during render, not set by an effect.** An
  effect-set tab stop means a menu rendered with `autoFocus={false}` (or server-rendered) has every
  row at `tabIndex -1` and no way in from the keyboard at all.

- 2026-09-30 **`RadioGroup` adds only Home/End; arrow keys stay native.** Real radios sharing a
  `name` already give the browser's arrow navigation and the single group tab stop.
  Reimplementing that on `role="radio"` divs is how a custom radio ends up worse than the
  platform. Browsers do not implement Home/End for radios, so that is the one gap filled.

- 2026-09-30 **`Checkbox` and `Radio` keep a real `<input>`, visually hidden rather than
  replaced.** That is where Space activation, form participation, the indeterminate/mixed state
  and label association come from. `indeterminate` is a DOM property with no React prop, so it is
  set in an effect; the element then reports `aria-checked="mixed"` natively.

- 2026-09-30 **`Toggle` is `role="switch"` on a `<button>`, not a styled checkbox.** `switch` is
  what makes a screen reader say on/off instead of checked/unchecked, which is the distinction
  Telegram's settings rows carry.

- 2026-09-30 **`TextField`'s floating label animates `inset-block-start`, not `transform`.** The
  first version used `translateY(calc(-50% - 16px))`, which is a magic number per size and put the
  label inside the box instead of on the border. Animating the offset from `50%` to `0` with a
  constant `translateY(-50%)` is size-independent and lands the label exactly on the border line,
  where its `--tg-surface` background cuts it.

- 2026-09-30 **A `label` forces `placeholder=" "` and ignores a caller's placeholder.** The float
  is pure CSS and needs `:placeholder-shown` to test emptiness. Telegram never shows a label and a
  placeholder at the same time, so this is a limitation with no cost — but it is a surprise if
  undocumented.

- 2026-09-30 **`Tabs`' underline is a pseudo-element on the selected tab, so it cross-fades and
  scales rather than travelling.** A single sliding bar has to be measured in JS, and the
  measurement is wrong on the first frame and after every webfont load. This is the one deliberate
  visual deviation from tweb in this task, and it is recorded rather than hidden.

- 2026-09-30 **`ScrollArea` scrolls natively.** A JS-driven scrollbar breaks momentum scrolling,
  `scrollIntoView` and find-in-page, and would fight `react-virtuoso` in TG-101 — the component
  that actually carries the message list. Styling is `scrollbar-color`/`scrollbar-width` plus
  `::-webkit-scrollbar`, because only the latter can make the bar float the way tweb's does.
  `focusable` defaults to **false**: a scroll region should be keyboard focusable when it has no
  focusable content, but a chat list is full of focusable children and a stop around each one
  doubles the tab stops in the window.

- 2026-09-30 **Contrast follows the TG-606 ruling, and no token was "improved".** Text on accent
  fills (`Button variant="filled"` / `"danger"`, `IconButton variant="filled"`, the selected chat
  row tint) keeps `--tg-text-on-accent` on `--tg-accent`, 3.31:1 on day. Body text uses
  `--tg-text-primary` / `--tg-text-secondary` / `--tg-text-danger` (`--tg-text-danger`, not
  `--tg-danger`, is used for the field error message and the danger menu row, because those are
  text). Decorative uses get a non-colour second signal: the online dot has a surface-coloured
  ring and the host carries `data-tg-online`; a selected `IconButton` changes icon colour as well
  as background and exposes `aria-pressed`; a checked menu row is `role="menuitemradio"` with
  `aria-checked`; an invalid field thickens its border and announces `role="alert"`.

- 2026-09-30 **No component library, and no new runtime dependency at all.** `@tg/ui` ships with
  zero runtime dependencies beyond the React peer. Everything a component library would have
  provided is here as a small internal module: `positioning.ts` (78 lines) instead of floating-ui,
  `focusOrder.ts` + `useFocusTrap.ts` instead of focus-trap, `cx.ts` (10 lines) instead of clsx.
  D-001 dropped PrimeVue because a general component library cannot produce Telegram's bubble
  tails, sidebar motion and sticker panel; reaching for Radix would repeat that.

- 2026-09-30 **Documentation is a Bun-served React gallery, not Storybook.** Storybook is a
  build-time dependency, a config surface and a second component model for 19 components.
  `bun ./src/docs/index.html` is Bun's built-in dev server with bundling and HMR — **zero new
  dependencies** — and it renders the real components rather than a hand-written copy of their
  markup, which is what a static HTML page would have meant (and would have drifted immediately).
  The page follows TG-009's `preview.html` shape: one demo tree rendered into two panes that
  differ only by `data-tg-theme`, with page × theme × accent × wallpaper in the URL fragment.

- 2026-09-30 **No DOM implementation was added for tests, and this constrains what is tested
  where.** `happy-dom`/`jsdom` is a new dependency and `AGENTS.md` plus `agent-protocol.md` §7
  reserve that decision. The consequence is a deliberate split, and a reviewer should know it:
  - **pure logic** (`rovingFocus`, `focusOrder`, `positioning`, `rippleGeometry`, `badgeText`,
    `initials`, `layerStack`, `galleryState`) is unit tested against fixtures. Those modules are
    pure *because* of this constraint, which turned out to be the right shape anyway;
  - **markup and ARIA** are asserted through `react-dom/server` (`src/test/*Aria.test.tsx`), which
    covers roles, names, `aria-*` state and the id wiring between labels and controls;
  - **live focus, key handling and geometry** were verified by driving a real headless Chrome over
    the DevTools protocol against the documentation page. That is not committed — see
    `Verification` for the exact results, and `Blockers` for the dependency request.

- 2026-09-30 **Test-side helper `src/test/markup.ts` parses the rendered HTML with regexes.** It
  is a test affordance, not a DOM: it only needs opening tags and attributes.

- 2026-09-30 **`packages/ui/.prettierignore` exempts `src/tokens/`.** `bun run -F '@tg/ui' lint`
  is red at the base commit `9010d69` on all 14 of TG-009's token files, which this task may not
  edit — and `bun run -F '@tg/ui' format` silently rewrote all 14 of them once during this task,
  which is how the file came to exist. Ignoring the directory fixes both. The alternative is in
  the integration patch list below; this is the integration lead's call, not mine.

- 2026-09-30 **`src/docs/docs.css` was split into `docs.css` + `docs-pages.css`** purely because
  the original was 362 lines against the repository's 350-line gate. Not a design boundary.

- 2026-09-30 **`DialogSurface` has an internal `inline` prop.** It renders in place instead of
  portalling. Its real use is a consumer that already owns a full-viewport layer root; its
  immediate use is the markup tests, which have no DOM to portal into. It is internal and not part
  of `Modal`'s or `Sheet`'s public props.

- 2026-09-30 **The split-theme gallery mirrors the pane you point at onto `<html>`.** Overlays
  portal into `document.body`, which sits outside both panes, so in split mode an open menu would
  paint with the root theme. The alternative — a portal-container prop on every overlay — is API
  surface added for a documentation need, so it was not taken. If M1 turns out to need scoped
  layer roots, that is the moment to add it.

a non-null ref.

Two smaller ones worth recording because they will recur:
- `useAnchoredPosition` re-rendered forever when a consumer built its anchor inline
  (`anchor={{ current: node }}`), because the memoised `measure` changed identity every render and
  the layout effect stored a fresh object each time. It now bails out when nothing moved.
- CSS beats an SVG **presentation attribute**, so `stroke-dasharray` in `Spinner.css` silently
  overrode the determinate arc computed in `Spinner.tsx` and every progress value rendered as the
  same sliver. The rule is now scoped to `:not(.tg-spinner--determinate)`.

## Residual risk

<!-- What a reviewer should distrust. Empty is a valid answer only if you looked. -->

- **The keyboard behaviour is proved by a browser run that is not in CI.** The pure keyboard rules
  (`rovingFocus`, `focusOrder`, `positioning`) are unit tested and the ARIA wiring is asserted on
  rendered markup, but the glue — "the effect ran against a live ref and moved focus" — is
  currently proved only by the DevTools-protocol session recorded under `Verification`. That glue
  is exactly where all five bugs found during this task lived. This is the highest-value item in
  this section, and integration patch 5 is the fix.
- **`react-dom/server` cannot render a portal**, so `Modal`, `Sheet`, `Popover`, `Menu`,
  `ContextMenu` and `Tooltip` are markup-tested through their portal-free surfaces
  (`DialogSurface` with `inline`, `MenuList`) rather than through the public component. A reviewer
  should read those tests as covering the surface, not the wiring.
- **The colour-literal scanner is lexical and has two known gaps**, both documented in the file:
  a computed value (`backgroundColor: props.tint`) cannot be judged from source text and is not
  flagged; and bare named colours are only checked in `.css`, because in TypeScript `'pink'` is far
  more likely to be an accent name than a colour. It stops the realistic accident, not a determined
  bypass.
- **`Tooltip` uses `cloneElement`** and therefore requires its child to forward a ref and DOM
  handlers. Every `@tg/ui` control does; an arbitrary third-party child may not, and the failure is
  silent (the tip never positions). A wrapper element would have changed layout, which is worse.
- **`ContextMenu`'s long press is a timer plus a movement threshold, not a gesture recogniser.** It
  does not know about scroll momentum or multi-touch. It was tested with synthetic pointer events,
  not on a real touch device.
- **`ScrollArea`'s overlay scrollbar is `::-webkit-scrollbar` on Chromium/Safari and
  `scrollbar-color` on Firefox.** The floating behaviour only exists on the former; Firefox gets a
  thin bar that is always present. Deliberate, but the two browsers do not look identical.
- **Every exit animation is timed by `usePresence`, which reads the element's own computed
  duration and adds 50ms.** If a consumer overrides a component's animation with a longer one via
  `className` and the element does not emit `animationend`/`transitionend` (for instance because
  the animation is on a child), the surface unmounts early. The listener checks `event.target ===
  node` precisely to avoid the opposite failure.
- **The seven avatar slots are indistinguishable today.** That is honest degradation rather than a
  bug, but a reviewer comparing against Telegram will see one colour where Telegram shows seven.
- **`Tabs`' indicator does not travel** (see Decisions). It is the one place where a reviewer
  holding a tweb screenshot next to this will see a real behavioural difference.
