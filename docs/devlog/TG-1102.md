## Frozen interface

- Account socket frame `{"type":"friend_statuses","statuses":[{user_id,status}]}`, sent when the
  serialized list changes, checked every 4th refresh tick (~3 s). Same function and privacy rules as
  `GET /api/friends/statuses`.

## Decisions

- 2026-10-01 Reused the account socket's existing poll-and-diff loop (it already pushes
  `social_changed` / `notifications_changed`) instead of fanning presence events out from every chat
  socket: one privacy-checked computation per viewer, no new pub/sub path.
- 2026-10-01 The friend query is ordered by id so an unchanged list never looks changed.
- 2026-10-01 The page uses the pushed list once one has arrived, the REST read before; the 60 s poll
  is gone.
