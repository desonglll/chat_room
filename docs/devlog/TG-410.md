## Frozen interface

- `POST /api/chats/:id/contact-messages` `{ user_id, reply_to?, topic_id? }` → 201 `StoredMessage`
  with `media_kind: "contact"` and `contact { user_id | null, username, display_name, avatar_emoji }`
  (also on the WS `broadcast` frame and in history; omitted on every other message).
- `GET /api/translation` → `{ available }`; `POST /api/messages/:id/translate` `{ target_language }`
  → `{ message_id, target_language, text }`; 503 when no AI provider, 404 when unreadable.
- Migration `20270101000010_add_message_contacts`.

## Decisions

- 2026-10-01 A card is an ordinary message plus a `message_contacts` snapshot of the shared
  account (Telegram shows the card as it was sent). It passes the normal gates: `message.send`,
  the TG-204/207 post gate (topic, slow mode), active membership. Anyone's card may be shared (the
  same public fields user search already exposes).
- 2026-10-01 The card's attach step looks up every loaded non-attachment message and sets both
  `contact` and `media_kind`: TG-302's media step only sets `media_kind` for attachment messages.
- 2026-10-01 Translation reuses the configured AI provider (`AiAssistant::translate`, same
  request/timeout pattern as extraction) — no new provider. It is a projection for the one viewer
  who asked, never stored over the original. With AI disabled (D-009) `/api/translation` says
  `available: false`, the client never shows «翻译», and the endpoint answers 503, not an error page.
  Read-time authorization: the viewer must be able to read the message's chat.
- 2026-10-01 «整聊天翻译模式» (translating a whole chat) is not built: with AI disabled it would be
  invisible, and per-message translation covers the need; left for when AI is turned back on.
