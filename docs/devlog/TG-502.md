## Frozen interface

**Server rule (DB trigger `chat_members_unarchive_on_message`, `AFTER INSERT ON messages`)** — a new
message sets `chat_members.is_archived = FALSE` (and bumps `preferences_updated_at`) for every
*active* member of that chat who (a) is not the sender (`sender_id IS NULL`, i.e. a system message,
counts), (b) has `notification_level <> 'none'`, and (c) has no `muted_until` in the future at
insert time. Muted-archived stays archived; main-list chats are untouched. No HTTP shape changed:
archive/unarchive keep using the existing `PATCH /api/conversations/{id}/preferences {is_archived}`,
and `GET /api/conversations` reports the result.

**Web (`packages/web/src/features/chatList/`)**
- `archiveRules.ts` (pure): `archiveBadge(conversations, nowMs) → {count, muted}` (sum of unread over
  archived non-muted chats; if 0, the muted sum with `muted: true` = grey), `unarchivesOnMessage(conv,
  senderId, currentUserId, nowMs)`, `withPreferences(convs, chatId, partialPrefs)`, `archivePreviewChats(convs, limit)`.
- `archiveActions.ts`: `setChatArchived({client, token, store}, chatId, archived) → Promise<boolean>`
  (optimistic, PATCH, rollback on failure); `applyUnarchiveRule(store, event, currentUserId, nowMs)`;
  `updateConversationPreferences(client, token, chatId, {is_archived?, is_pinned?})`.
- `archiveRowMode.ts`: `'collapsed' | 'expanded' | 'hidden'`, persisted per device under `tg.archive.v1` (`{mode}`), default `collapsed`.
- `ArchiveRow` props: `{mode, previewChats, count, badge, now, collapsed?, onOpen, onModeChange}`; exports `ARCHIVE_TITLE = '已归档的对话'`.
- `ArchivableChatRow` props: `{archived, collapsed, onToggleArchive, children}`; `archiveMenuItems(archived, onToggle)` for any other chat menu to reuse.
- `SwipeArchive` props: `{archived, onCommit, disabled?, children}`; `swipeGesture.ts` pure decisions.
- `startAccountFeed` options gained optional `currentUserId?: () => string`.
- `ChatListView` gained `archived: ConversationSummary[]`. `avatarParts` in `chatRowModel.ts` is now exported.

## Decisions

- 2026-10-01 The unarchive rule is a **database trigger**, not code in a send path, because messages
  are inserted by nine paths across other tasks' modules (text/WS, forward, sticker, poll, attachment,
  favorites, AI…); a trigger makes every one of them obey the rule without touching their files, and it
  follows the existing `notifications_*_insert` trigger precedent. Chosen over a read-time derivation
  (`archived_at` watermark + "any newer message not muted at its time") because mute state at *arrival*
  is what Telegram uses and a derivation cannot know it after an unmute; the trigger decides at arrival.
- 2026-10-01 SQLite compares `julianday(muted_until) <= julianday('now')`, not the raw TEXT, because
  `muted_until` is RFC 3339 with `T`/offset while `CURRENT_TIMESTAMP` uses a space; lexical comparison
  would be wrong within the same day.
- 2026-10-01 The sender's own message never unarchives (Telegram behaviour; also the account socket never
  echoes own messages). A system message (`sender_id NULL`) counts like any other, consistent with the
  unread count, which also counts it.
- 2026-10-01 "Muted" = `isConversationMuted` (level `none`, or `muted_until` in the future). Level
  `mentions` is *not* muted, and an expired `muted_until` is not muted — both are in the test matrix.
- 2026-10-01 Unmuting an archived chat does not replay the message that arrived while muted; only the
  next message unarchives it (asserted in the Rust test) — this falls out of deciding at arrival.
- 2026-10-01 The client mirrors the rule on the account socket's `new_message` (`applyUnarchiveRule`)
  so the row moves immediately; the next REST resync reads the trigger's result, so the two cannot drift
  for longer than one resync.
- 2026-10-01 Archive badge: accent sum over archived non-muted chats; when that is 0, the muted sum in
  grey. (TG-102's row was always grey; the lead's card asks for the loud/quiet split.)
- 2026-10-01 Archive row default is `collapsed` (thin avatar-stack row) with `expanded` and `hidden`
  via its context menu; hidden puts "已归档的对话" (+ unread count hint) and "在列表顶部显示归档" in the
  hamburger menu. Per-device localStorage like `tg.sidebar.v1`, because it is a view preference, not account data.
- 2026-10-01 Swipe: touch pointers only (mouse drag stays a link drag; desktop uses the context menu);
  `touch-action: pan-y` so a vertical scroll cancels the pointer and never archives; axis lock at 10 px;
  commit past 35% of the width or on a leftward flick ≥0.6 px/ms; rubber band past full width. Fly-out
  and spring-back both use TG-009's `smooth` spring (critically damped): `standard` (ζ≈4.6) left a
  visible slow tail and delayed the commit, `bounce` overshoots right of rest and exposes the strip's
  left edge. Reduced motion: no spring, the row snaps and the commit is immediate. The spring is driven
  with `motion`'s `animate` (already in the bundle via the media viewer).
- 2026-10-01 The folder view closes itself when its last chat is unarchived (Telegram does the same).
- 2026-10-01 Styles live in `features/chatList/chatArchive.css` (imported from `styles/index.css`) because
  `styles/chatList.css` is at 336 lines, near the 350 warning.

## Residual risk

- The trigger runs inside every message insert's statement. It is one indexed `UPDATE chat_members …
  WHERE room_id = ? AND is_archived` (hits `chat_members` by `room_id`); for a huge channel with many
  archived members this is a write per archived member per message — same order as Telegram's own
  semantics, but a PG `EXPLAIN` on a large chat is worth one look at M6 load test.
- PostgreSQL restore (`pg_restore`) creates triggers in the post-data section, so restored rows do not
  fire it; SQLite restore is a file copy. Verified by reading `src/backup/*`, not by a test.
- Messages whose insert is rolled back never unarchive (same transaction) — correct, noted for clarity.
- The client mirror uses the local clock for `muted_until`; a skewed clock can show the row in the wrong
  folder until the next resync (the server is authoritative).
- Swipe was verified with CDP-synthesised touch events in headless Chromium, not on a physical device.
