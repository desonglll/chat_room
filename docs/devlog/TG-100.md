## Frozen interface

### `messageStore` (packages/core) — additive except one field

- `ChatTimeline.readCursors: Record<user_id, message_id>` (new required field; the only
  literal outside the store, the TG-101 bench harness, was updated).
- `prependHistory(chatId, page: BroadcastMessage[]): number` — puts an older REST page
  (any order, may overlap) in front of the timeline; only messages strictly older than the
  oldest server message present are taken; returns the count added; no-op keeps identity.
- `applyReadReceipts(chatId, receipts: {user_id, message_id}[])` — `auth_ok.read_receipts`
  snapshot and each `read_receipt` frame.
- `peerReadThrough(timeline, viewerId): string` — newest timestamp another member read
  through among loaded messages ('' = none) → the outgoing double tick.

### `ChatSession` (features/chat/chatSession.ts)

- `sendFrame(frame: ClientFrame): boolean` (TG-104 patch 1) and `markRead()`; option
  `isVisible?: () => boolean`. `setDraftText` no longer sends typing frames (TG-104 patch 2:
  the composer's TG-107 chat-action sender owns typing). `stop()` now clears the chat's
  timeline (the next open replays from the server; a kept timeline silently skipped every
  message that arrived while the chat was closed).
- Frames newly fanned out: `auth_ok.read_receipts`, `read_receipt`. Outbound: `read` for the
  newest server message on `history_complete`, on each incoming live arrival, and when the
  page becomes visible — never while hidden.

### Message list controller (features/messageList, seam only)

- `MessageListControllerOptions.prependLive?(rows): number` — when set (the app always sets
  it), live-mode older pages and jump windows that join live go INTO the message store, so
  edits / recalls / reactions / read ticks reach every loaded row. The private `older` array
  remains only for tests that omit it. Anchor math unchanged (key-based; `before` is captured
  ahead of the store write).
- The list no longer adds a row gap (the TG-103 row owns rhythm); its highlight band only
  applies to rows without a TG-103 bubble (`:not(:has(.tg-message))`).
- `MessageRenderContext` is declared once in `messageList/renderContract.ts`;
  `features/message/types.ts` re-exports it (`GroupPosition` = its `groupPosition`).

### App-wide chat surfaces (features/chat)

- `ChatOverlays` (mounted once in `WorkspaceShell`): `<MediaViewer>` with forward / delete /
  canDelete bound (download = the viewer's `<a download>` default), `ForwardDialog`,
  `DeleteConfirmDialog`.
- `chatDialogStore.ts`: `requestForward(fromChatId, ids)`, `requestDelete(chatId, ids):
  Promise<boolean>` (recall frames through `chatSessionRegistry.sendChatFrame`).
- Forward flow: pick a chat → `dispatchMode(target, {type:'forward', …})` → navigate there;
  the composer's forward bar + send performs `POST /api/messages/forward`.

## Decisions

- 2026-10-01 Older pages go INTO `messageStore` (`prependHistory`) through an optional controller
  port `prependLive`, rather than an overlay of "patches" over the list's private `older` array,
  because the store timeline is then the one loaded window every consumer already reads (edits,
  recalls, reactions, read ticks, the composer's reply/edit bar lookup, the media viewer seed) and
  the anchor math stays key-based. The controller keeps `older` only when the port is omitted
  (unit tests), so TG-101's controller tests still run unchanged.
- 2026-10-01 `getLive` in `useMessageListController` reads the store, not the last rendered prop,
  because the prepend shift must see the rows written a line earlier in the same tick.
- 2026-10-01 `ChatSession.stop()` clears the chat's timeline, because the server replays the last
  100 messages on every join and `mergeIncomingBroadcast` appends: a kept timeline (now up to many
  REST pages) would sit in front of the replay with a silent gap for everything that arrived while
  the chat was closed. Cost: reopening shows the spinner until `history_complete` (as a first open).
- 2026-10-01 Read receipts live in `messageStore` (`readCursors`) and the double tick is derived
  (`peerReadThrough` → `deliveryFor`) instead of a per-message flag, because the wire carries one
  cursor per user. The session now sends `read` itself (history complete, each incoming arrival,
  page becoming visible) — nothing sent `read` before, so no tick ever doubled.
- 2026-10-01 Bubble actions are bound in a framework-free `bindMessageActions` with permissions
  mirrored from the server (edit/recall own only; pin = private chat or owner/admin), because an
  absent callback is how the bubble hides a control and the rules need a unit test.
- 2026-10-01 Root-level surfaces (media viewer, forward picker, delete confirm) reach a chat's
  socket through `chatSessionRegistry` (registered by `useChatSession`) rather than a second socket
  or prop-drilling, because the viewer is mounted in the shell, outside the chat pane.
- 2026-10-01 Forward = pick chat → composer forward bar in the target chat → send (TG-104's
  controller calls `forwardMessages`), Telegram Desktop's flow, so a forward can carry a comment
  and be cancelled.
- 2026-10-01 Delete asks for confirmation and recalls for everyone; the server has no
  "delete for me".
- 2026-10-01 Selection mode replaces the composer with a selection bar (count / 转发 / 删除 / ✕,
  Esc cancels); 删除 is enabled only when every selected message is the viewer's own and live.
- 2026-10-01 MediaViewer is mounted by `WorkspaceShell` (via `ChatOverlays`), not `App.tsx`, because
  forward navigates (needs the router) and `src/App.tsx` is outside my paths. Download is the
  viewer's default `<a download>`.
- 2026-10-01 ChatPane subscribes to primitives (`peerReadAt` string, `selectionDeletable` boolean),
  not the timeline, so it and the composer do not re-render on every message frame.
- 2026-10-01 The chat descriptor is refetched (`getChat`) when the open chat's participant count
  changes (or differs from `member_count` at connect), so a join while the chat is open can reach
  the header.
- 2026-10-01 The list's highlight band applies only to rows without a TG-103 bubble
  (`:not(:has(.tg-message))`), because the bubble row draws its own wash; two stacked looked doubled.
- 2026-10-01 Cargo builds use the private `CARGO_TARGET_DIR=/home/mike/workspace/.cargo-target/tg-100`
  (lead notice, Hazard 2) with `CARGO_BUILD_JOBS=6 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0`;
  the lead may delete that directory after merge.

## Residual risk

- `read` is sent whenever the page is visible and a message arrives, even if the reader is scrolled
  far up (Telegram marks per viewed message), so unread counts clear on arrival while open.
- Rows in a DETACHED jump window keep their fetched state until the window joins live.
- System frames (`{user} joined the room`) are still not rendered (the session never subscribed to
  `system`); unchanged by this task.
- Image rows grow after load (no dimensions on the wire); the list re-follows to the bottom (E2E
  asserts it), but a smooth scroll in progress can briefly show the image cut off.
- `canDeleteAll` only sees store rows; a selection made in a detached window disables 删除.
