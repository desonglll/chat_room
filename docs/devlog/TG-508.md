## Frozen interface

- `GET /api/users/me/notification-settings` → `{ defaults: [{ scope, enabled, preview, sound }],
  exceptions: [{ chat_id, chat_title, enabled?, preview?, sound? }] }` (only readable chats listed).
- `PUT /api/users/me/notification-settings/defaults/:scope` (`private|group|channel`).
- `PUT /api/chats/:id/notification-exception` `{ enabled?, preview?, sound? }` — all null removes it.
- Sounds: `default, note, chime, pop, bell, none`. Web Push payload gains `silent` (sound `none`)
  and drops the body when the chat's preview is off.
- Migration `20270201000007_notification_exceptions`.

## Decisions

- 2026-10-01 The existing per-chat `chat_members.notification_level` / `muted_until` stay the mute
  switch (1 h / 8 h / 2 d = `muted_until`, which lifts by itself; «永久» = level `none`), so the
  frozen clients and every existing test keep their meaning. New: a default per chat type and a
  per-chat exception (NULL = inherit) for on/off, preview and sound.
- 2026-10-01 One pure rule, `notifications::exceptions::decide`, with a unit-test matrix: timed
  mute > exception `enabled` > legacy level (`none` / `mentions`) > type default. Push delivery
  calls it (`chat_push_decision`), which also yields the preview switch and the sound;
  `chat_allows_push` survives only for the existing delivery unit tests.
- 2026-10-01 Sound is a stored preference; browsers cannot choose a Web Push sound, so the server
  honours only `none` (a silent notification). In-app playback belongs with the PWA work (TG-601).
