## Frozen interface

- WS `message` frame: optional `reply_quote: { text, offset? }` (UTF-16 offset) and
  `reply_to_chat_id` (the replied message lives in that chat).
- `ReplyPreview` (REST history and WS broadcast) gains optional `quote { text, offset }`,
  `quote_modified`, `chat_id`, `chat_title`; all omitted when empty, so older frames are byte-identical.
- Migration `20270101000009_add_reply_quotes`: `messages.reply_quote_text`, `reply_quote_offset`
  (BIGINT on PostgreSQL), `reply_to_chat_id`, `reply_source_sender`, `reply_source_chat_title`.

## Decisions

- 2026-10-01 A quote must be a real slice of the original (checked server-side in UTF-16 units,
  like TG-304 entities, capped at 1024 units); a quote that does not match is dropped, the reply
  kept — a message is never refused over its quote.
- 2026-10-01 Cross-chat: allowed only if the sender can read the source chat; otherwise the
  message goes out as a plain message (graceful degradation). The target chat sees a SNAPSHOT
  taken at send time (source sender, source chat title — «私聊» for a private chat — and the quote
  or the first 200 characters). The live reply join in `MESSAGE_SELECT` is now restricted to the
  same chat (`reply.room_id = messages.room_id`), so no read path can expose the rest of a source
  message to members of the target chat. Opening the source is a deep link; the server's
  ordinary authorization decides whether the viewer may see it.
- 2026-10-01 «已修改»: the original's `edited_at` is later than the quoting message's
  `created_at` (a timestamp only, no content, even across chats).
- 2026-10-01 Client: the quote/source live beside the composer drafts (`replyExtras`), not in
  them — the cloud draft (TG-008) syncs only the reply target — and drop whenever the target
  changes. «引用» reads the selection when clicked (a JS string index is the UTF-16 offset);
  «在其他聊天中回复» reuses TG-100's forward picker with a `replyTo` request.
- 2026-10-01 Only text messages sent over the WebSocket carry quotes / cross-chat replies;
  media sends keep ordinary same-chat replies.
