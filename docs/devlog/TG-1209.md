## Findings (before code)

- **Where the CSP is built**: `src/security/headers.rs` — a `&'static str` constant with `img-src 'self' data: blob:`, applied by `security_headers` (`axum::middleware::from_fn`, `src/lib.rs`). It could not know the deployment's tile host.
- **How TG-407 tiles are configured**: `src/config/map.rs` `MapConfig.tile_url` (default `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, env `CHAT_ROOM_MAP_TILE_URL`), validated to be http(s) or a same-origin path; exposed to the client as `map_tile_url` in `/api/config`; Leaflet (`features/location/locationApi.ts`) draws tiles as `<img>` from it. So production tiles were blocked by `img-src`.
- **TG-408 fetcher and SSRF guard**: `src/messages/link_previews/fetch.rs` (hop loop: `ssrf::check_url` → resolve once → `ssrf::pick_address` checks every answer → reqwest pinned to that address via `resolve`, no env proxy, redirects by hand, one 5 s deadline, body cap) + `ssrf.rs` (`Policy`: http/https only, ports 80/443/8080/8443, no credentials, public unicast only incl. v4-in-v6 forms). `parse.rs` kept `og:image` as an absolute http(s) URL **that the browser loaded directly** — blocked by `img-src`, and had it been allowed, every viewer's browser would have contacted the third-party host.

## Frozen interface

- `LinkPreview.image_url` (REST history, `link_preview_updated` frame, `GET /api/link-preview`): **always** `null` or a same-origin path `/api/link-previews/images/{key}` — never a third-party URL. Shape unchanged (still `Option<String>`), so no client change was needed.
- `GET /api/link-previews/images/{key}` → 200 with the stored bytes, `content-type` ∈ {image/png, image/jpeg, image/gif, image/webp}, `cache-control: private, max-age=86400`, `content-disposition: inline`; 404 for an unknown key or when the page's cache entry is no longer ok. No session header: the key is the capability (same model as `/api/attachments/:id?key=`, because `<img>` cannot send `Authorization`).
- DB: `link_preview_images (url PK → link_previews.url ON DELETE CASCADE, access_key UNIQUE, content_type, data, fetched_at)`, migration `20271201000001_add_link_preview_images` in both adapters.
- CSP: `img-src 'self' data: blob:` plus exactly one source derived from `map.tile_url` (none for a same-origin path). Built once at startup: `security::content_security_policy(tile_url) -> HeaderValue`; `security_headers` now takes it as `State<HeaderValue>`.

## Outbound fetch paths (for lead review — SSRF-sensitive)

1. **Page fetch** (unchanged behaviour): `fetch::fetch_preview` → `fetch_bounded(.., &HTML)` → `fetch_hops`. Guards: `check_url` + `pick_address` on every hop, DNS pinned, redirects ≤ 3 re-checked per hop, no proxy, 5 s total deadline, body truncated at 256 KiB, content-type must be HTML.
2. **Card image fetch (new)**: `images::fetch_card_image` → `fetch::fetch_image` → the **same** `fetch_bounded`/`fetch_hops` with `&IMAGE`. Identical guards (same `Policy` from `AppState::link_preview_policy`, same hop/DNS/redirect/deadline rules), plus: `Accept` raster types only; header must be `image/*`; `Content-Length` > 1 MiB refused up front and the stream is aborted the moment it would exceed 1 MiB (`TooLarge`, never truncated/stored); the stored type comes from **magic bytes** (`sniff_image`: PNG/JPEG/GIF/WebP) — SVG or anything else → `NotImage`, nothing stored. It runs under the same global `FETCHES` semaphore permit as its page (max 4 concurrent outbound fetches server-wide), only when previews are enabled, only after the page fetch succeeded and named an absolute http(s) `og:image`.
- There is no other new outbound path. The tile host is never fetched by the server; it only appears in the CSP.
- Tests: `tests/link_preview_images_test.rs::card_images_are_checked_like_pages_and_judged_by_their_bytes` (SVG-as-PNG refused, oversize refused, redirect to 169.254.169.254 refused, internal host refused without the fixture exemption) on top of the TG-408 suite in `tests/link_preview_test.rs`, which still passes over the refactored hop loop.

## Decisions

- 2026-10-01 Serve card images through the server instead of adding image hosts to the CSP, because the host set is unbounded (any page names any image host) and a direct load would leak every viewer's IP/UA to third parties; the card already said "the browser loads it, not the server" — that was the defect.
- 2026-10-01 One generic hop loop (`fetch_bounded` with a `Kind`) instead of a second fetcher, because two copies of the SSRF hop logic would drift; the HTML path's behaviour (truncate at 256 KiB, `NotHtml`) is unchanged and the existing TG-408 tests prove it.
- 2026-10-01 Capability key (random UUID) instead of a session-checked route, because `<img>` cannot send the bearer header and this matches attachments; the key is stable across re-fetches of the same page (`ON CONFLICT (url) DO UPDATE` keeps `access_key`) so cards already on screen keep working. Authorization is no weaker than the composer endpoint: any signed-in user can already request the preview of any URL.
- 2026-10-01 Store image bytes in the DB (≤ 1 MiB, one per cached page, cascades with the page) rather than the attachment storage backend, because these are disposable projections of a third-party page, not user content; no OSS/local-storage lifecycle needed.
- 2026-10-01 Sniff the type from bytes and refuse SVG, because a same-origin SVG is an active document; with `nosniff` the stored, sniffed type is what the browser uses.
- 2026-10-01 `cache-control: private, max-age=86400` (not `immutable`) because the bytes behind a stable key can change on a later re-fetch.
- 2026-10-01 Tile CSP source: `{s}.` as the first host label → `*.host` (Leaflet subdomain rotation); any other placeholder in the host → nothing added + a startup warning; the source is rebuilt from the parsed URL and limited to `[a-z0-9.-]`, so a config value cannot inject directives (`;`, `,`, spaces). Kept in `src/security/csp.rs`, not in `config/map.rs` (outside my paths); `MapConfig::validate` is unchanged.
- 2026-10-01 Cards cached before this migration have no stored image: their `image_url` is `null` until the 24 h cache entry is re-fetched. Accepted rather than a backfill job — a backfill would be a burst of outbound fetches at startup.

## Residual risk

- The default deployment now allows `https://tile.openstreetmap.org` in `img-src` (that is D-010's chosen default, previously silently broken). Deployments that must not contact OSM set `map.tile_url` to their own server or a same-origin path, which removes the allowance.
- Image bytes live in the main DB (≤ 1 MiB × distinct previewed pages). There is no size-based eviction beyond the 24 h refresh replacing rows in place and `link_previews` deletion cascading; nothing deletes stale `link_previews` rows today (pre-existing TG-408 property).
- `GET /api/link-previews/images/{key}` is not rate-limited; it only serves already-stored bytes (no outbound fetch), keys are random UUIDs.
