## Frozen interface

TG-101 (virtual message list), TG-102 (sidebar), TG-103 (bubbles), TG-104 (composer) and
TG-107 (typing/presence UI) replace pieces of this shell; what they may rely on is exactly
this section. Everything wire-shaped is someone else's frozen contract (TG-004 §5 HTTP,
TG-007 WS frames, TG-008 drafts, TG-011 core modules) — this task adds **no** wire contract.
What it freezes is the app-side seams.

### 1. Routes (react-router-dom, history mode)

| path | screen | notes |
| --- | --- | --- |
| `/login` | login/register page | redirects to `/` when a session exists |
| `/` | three-pane shell, empty state | redirects to `/login` when no session |
| `/chat/:chatId` | shell with the chat open | the route record name for deep links is `chat`, matching `domain/messageDeepLink`'s default; `?message=<id>` is reserved for TG-101's jump-to-message and is not consumed yet |

The server serves `index.html` for any unmatched path (`build_app_with_web` fallback), so
history-mode URLs survive refresh. M1+ adds routes; these three keep their meaning.

### 2. Platform adapters (`packages/web/src/app/platform.ts`)

The browser implementations of `@tg/core`'s injected capabilities, importable by every
later feature task instead of re-touching a global:

- `browserFetch: FetchLike` — `window.fetch` bound to `window`; the ONE fetch every api
  module uses (core has no global default by design).
- `browserStorage: CoreStorage` — `localStorage` behind try/catch (private-mode safe).
- `browserClock: CoreClock` — `Date.now` + window timers.
- `createBrowserSocket: CoreSocketFactory` — WHATWG `WebSocket` → `CoreSocket` adapter.
- `chatSocketUrl(chatId)` — `ws(s)://<host>/ws/<chatId>` from `location`.

### 3. App singletons (`packages/web/src/app/client.ts`, `session.ts`)

- `apiClient` — the one `createApiClient({ fetchImpl: browserFetch, baseUrl: '' })`.
- `draftsApi` — `createDraftsApi(browserFetch, { token: () => authStore token })`.
- Session persistence: key `tg.session.v1` in `CoreStorage`, value the raw `AuthSession`
  JSON. `hydrateSession()` restores an unexpired session into `authStore` at boot and
  re-validates via `GET /api/users/me` in the background (401 → clear + `/login`).

### 4. The chat wiring seam (`packages/web/src/features/chat/chatSession.ts`)

`createChatSession(deps)` is the ONE place a socket meets the stores. TG-101/103/104/107
extend its frame fan-out rather than opening second subscriptions elsewhere. Deps are all
injected (socket factory, clock, api client, drafts api, the five stores) so the whole
lifecycle runs under `bun test` against fakes. Behaviour frozen for M1:

- frame fan-out: `auth_ok`→presence+statuses, `history_complete`→`setHistoryReady(true)`,
  `broadcast`→`messageStore.applyBroadcast` with `classifyMessageMotion`, `presence`,
  `typing` (+host-driven expiry via the injected clock), `user_status`, `message_edited`,
  `message_recalled`, `reaction_changed`, `chat_updated`→chatListStore, `draft_updated`→
  the draft policy below.
- reconnect catch-up: `fetchMissed` = REST `GET /api/chats/:id/messages` page, reversed to
  chronological order; dedup stays in `mergeIncomingBroadcast` (idempotent on message_id).
- send path: optimistic append (`createRandomUuid` client id) → WS `message` frame →
  broadcast reconciles; a send while offline marks the row `failed`.
- **draft policy («打字的键盘赢»)**: every remote draft state (WS `draft_updated` frame,
  `GET` result at open, `PUT` response) goes through `draftSynchronizer.accept()` FIRST;
  it is applied to `composerStore` only when `pending(chatId)` is false. A local edit
  mid-debounce therefore never gets clobbered — the queued local content overwrites the
  server on commit, which is exactly `domain/draftSync`'s documented accept semantics.
  Local edits go `composerStore.setDraftText` + `synchronizer.update` (1.5 s debounce);
  send and chat-switch call `flush()`. **No core change was needed** — see Decisions.

### 5. Store subscription form

`packages/web` subscribes to the nine `@tg/core` vanilla stores exclusively via
`useStore(xxxStore, selector)` from `zustand/react`. No store state is copied into React
state, no context provider wraps them. Later tasks keep this form.

### 6. UI copy

UI copy is Chinese, lives in the page components (M0 volume does not justify an i18n
layer), and maps `ApiError.status` → human copy at the feature boundary. The frozen wire
strings (`auth_fail` reasons etc.) are matched only inside core; the shell never
string-matches wire content.

## Decisions

- 2026-09-30 **react-router-dom@^7 + zustand@5.0.8 added to `packages/web` only** — both
  pre-approved dependency grants on this task's card (react-router-dom for the routing
  skeleton; zustand because `useStore` from `zustand/react` is the mandated subscription
  form and peer-resolving it through `@tg/core`'s copy would be an undeclared dependency).
  Same zustand version as core pins, so bun dedupes to one copy. `bun.lock` regenerated by
  `bun install`, no other entries changed.
- 2026-09-30 **The draft seam is closed in the web wiring layer, not by patching
  `composerStore`.** The audit's gap: `composerStore.applyDraftUpdated` guards only by
  `updated_at`, and a local-only draft has `updatedAt: ''`, so a remote frame arriving
  mid-debounce would clobber the keyboard. Fix chosen: `chatSession` routes EVERY remote
  draft through `draftSynchronizer.accept()` and applies it to the store only when no
  local save is pending. `draftSync.accept` already implements "the typing keyboard wins"
  (differing queued content stays queued and overwrites on commit), so a store-level
  policy fix would duplicate policy in a second place and need a second clock. No
  integration patch to `packages/core` is therefore required for TG-012 — but if a later
  task wants the store self-guarding, the diff is recorded under "Integration patch
  candidates (not required)" below.
- 2026-09-30 **Message history comes from the server's WS replay, not a parallel REST
  load.** The server replays `history_replay_limit` messages between `auth_ok` and
  `history_complete` on every (re)connect; for the M0 shell a REST page would race the
  replay for zero benefit (merge is idempotent either way). REST history enters with
  TG-101's pagination. The REST client is still exercised: it is the reconnect
  catch-up (`fetchMissed`) and the probe suite's persistence check.
- 2026-09-30 **New chats are created open and passwordless from the shell**
  (`join_policy: 'open'`, `password: null`), so the WS greeting is always `join`. The
  password/`auth` path exists in core and in the server; its UI (password prompt, vault)
  is M1/M2 surface. `has_password` chats joined elsewhere still render; sending into them
  simply requires no password because membership was already established.
- 2026-09-30 **Typing send is a 1 Hz throttle inside `chatSession`, not
  `domain/textFrameBatch`.** textFrameBatch batches per animation frame — the wrong axis
  here (network etiquette, not paint); the old client's schedule was time-based too. The
  throttle uses the injected clock, so it is test-driven like everything else. `cancel`
  is sent when the composer empties, per TG-007 §1's preference for explicit cancel.
- 2026-09-30 **System frames render as a connection-status line, not timeline rows.**
  `messageStore` has no append-system action (TG-011 deliberately left system rows to the
  milestone that renders them properly, M1); inventing one would be a core edit this task
  must not make. The shell shows join/leave content transiently in the header status
  area instead. Recorded as a residual gap for TG-103.
- 2026-09-30 **Theme: `settingsStore.theme` drives `data-tg-theme` on `<html>`; `system`
  resolves via `prefers-color-scheme`.** TG-009's token contract (day is the `:root`
  default, night is `[data-tg-theme="night"]`) makes this a three-line effect; the
  settings UI itself is M5 — the shell only honours the stored preference and the OS.
- 2026-09-30 **CSS lives in per-feature files imported from one `styles/index.css`, never
  from `.tsx`.** Same reasoning as `@tg/ui`'s single-stylesheet rule: `bun test` imports
  the components without a CSS loader. Every rule reads `--tg-*` semantic tokens only —
  checked by a web-side token-discipline test cloned from `packages/ui`'s.
- 2026-09-30 **Auth error copy maps status codes, not server strings.** `ApiError`
  carries `status`/`serverMessage`; the page maps 400/401/403/409/429 to Chinese copy and
  falls back to a generic line. Server `error` strings stay unmatched so backend copy can
  change freely (TG-011 decision "API error copy does not migrate" carried through).

## Residual risk

- **No real browser drove this shell.** The probe proves the transport contract and the
  unit tests pin the client wiring against fakes, but rendering, routing transitions,
  focus behaviour, theme switching and the actual two-browser walk-through have not
  been SEEN. That QA remains for the user; do not read step 07 of the probe as "a
  second browser rendered the message".
- **Draft clear vs in-flight save race.** If a message is sent inside the ~request
  round-trip after a draft commit started, the clearing `PUT ""` can race the in-flight
  content PUT; HTTP gives no ordering guarantee, so the server could keep a stale
  draft. Window is milliseconds against a 1.5 s debounce; the next draft edit or the
  other device's `draft_updated` self-heals. TG-104 owns the composer rewrite and can
  serialize the two if it ever shows up in practice.
- **`field-sizing: content` (composer auto-grow) is Chromium/Safari-current; Firefox
  falls back to a fixed-height scrolling textarea.** Cosmetic-only degradation, capped
  by `max-height`; TG-104 replaces the composer anyway.
- **System frames are not timeline rows yet** (join/leave lines) — `messageStore`
  deliberately has no system-append action (TG-011 left it to M1); TG-103 renders them.
- **Bundle is one 359 kB entry chunk.** Fine for M0; TG-101 (react-virtuoso) and M3
  (lottie-web + pako) will need manual chunking — noted so the size jump does not
  surprise the next owner.
