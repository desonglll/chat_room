## Frozen interface

- Content kind `bigEmoji` (priority 5, frame `bare`, meta overlay): text-only message (no
  attachment, no `media_kind`, no entities) of 1–3 emoji graphemes; `bigEmojiCount(text)`.
- Tokens: `--tg-motion-send`, `--tg-motion-burst`, `--tg-big-emoji-{1,2,3}` (+ raw 44/56/72px).

## Decisions

- Send flight: the viewer's own fresh message (TG-108 `data-fresh`, < 3 s at mount) rises from
  the composer edge with a scale-up on the smooth spring, origin bottom-right. No real
  composer→bubble geometry morph: it would need measuring both rects and risks layout jank in
  the virtualised list; the rise reads the same at chat speed.
- Reaction burst: plays only when the viewer's own reaction goes false → true while the chip is
  mounted (state adjusted during render, no effect); pop + ring on the bounce spring, keyed so a
  re-react replays it. History never bursts.
- Big emoji: Intl.Segmenter graphemes, `Extended_Pictographic`/regional indicators/keycaps;
  whitespace allowed between; > 3 or any other character → normal text bubble. Entrance pop on
  arrival, tap replays a "poke" wobble.
- Only transform/opacity animate → no layout shift. Reduced motion: moving keyframes swap to a
  fade (send, big-emoji entrance), burst/poke are dropped (ring becomes a brief flash).
