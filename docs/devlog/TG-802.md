## Frozen interface

- `GET /api/conversations` → `last_message.media_kind?: string`, and the account socket
  `new_message` frame → `media_kind?: string`. Vocabulary: `voice`, `video_note`, `sticker`,
  `gif`, `poll`, `location`, `live_location`, `contact`, `album`, `photo`, `video`, `audio`,
  `file`. Omitted for plain text. Additive; older clients ignore it.
- `POST /api/messages/forward` → a pair refused by the recipient's TG-505 `voice_messages`
  rule has `skipped_reason: "voice_messages_restricted"` (same code as `POST /api/chats/:id/voice`).
  Applies to voice and round-video sources forwarded into a private chat; groups unaffected.
- Core: `PreviewMediaKind` type, `ConversationLastMessage.media_kind?`, `AccountMessageEvent.media_kind?`.

## Decisions

- 2026-10-01 Classify on the server (`src/conversations/preview_media.rs`) instead of sending
  MIME + flags to the client, because the preview has two producers (REST list and account
  socket) that must agree; one Rust function + one SQL column macro serves both. The live
  timeline mirror (`previewMediaKind.ts`) re-derives from the full message it already has,
  with the same precedence (poll > dedicated media_kind > location > MIME, album for grouped
  photo/video), pinned by tests on both sides.
- 2026-10-01 The column set is a `macro_rules!` expanding to a string literal so the
  conversation query stays one `concat!` literal (no runtime `format!` on the hot list path).
- 2026-10-01 A forward refused by privacy is a per-pair `skipped_reason`, not a 403, because
  the endpoint is a batch and already reports partial results that way.
- 2026-10-01 Client notice reuses the voice recorder's copy 「对方设置了不接收你的语音消息」
  and is shown under the target chat's composer (where the forward was submitted) for 5 s.
- 2026-10-01 The extension guess is kept only as a fallback for previews without `media_kind`.
