## Decisions

- **No new dependency**: a ~100-line runtime in core (`i18n/runtime.ts`) — catalogs per locale,
  `translate(key, ...args)` with positional `{0}` slots, plural tables picked by the first
  numeric argument through `Intl.PluralRules` (each language brings its own rule), fallback to
  zh-CN then to the key. `localeStore` (zustand) is the switch.
- **Extraction by AST codemod** (`scripts/i18n/extract.ts`, TypeScript compiler API): every Han
  string literal, template (→ `{n}` slots), JSX text and JSX attribute → `t('key', …)`;
  module-scope object properties → getters so tables follow a language switch; other
  module-scope constants were converted by hand into functions (`archiveTitle()`,
  `loadFailedNotice()`, `lastSeenOfflineText()`, `unknownActorName()`, weekday names).
  Keys are `<w|c>.<area>.<hash>`; 1,149 web + 55 core messages.
- **Catalogs**: zh-CN source and English, one file per feature area under
  `packages/web/src/i18n/{zh,en}/` (31 areas) and `packages/core/src/i18n/{zh,en}.ts`.
  English has plural tables where English needs them (members, comments, messages, days …).
- **Switching without reload**: `settingsStore.language` (persisted) → `setLocale` +
  `<html lang>`; `LocaleRoot` re-keys the React tree on locale change so memoised components
  re-read their copy; stores, router and session survive. 设置 › 语言 offers 简体中文 / English.
- **«上次上线» rules per language**: the last-seen phrases are messages with slots and plurals
  («N 分钟前上线» / "last seen N minutes ago", today/yesterday/date forms).
- **CI gate**: `packages/web/test/noHardcodedChinese.test.ts` parses every web and core source
  (not tests, fixtures, the list benchmark harness, docs pages, or the catalogs) and fails on any
  Han character in a string, template or JSX text; comments are ignored. Catalog completeness and
  slot parity are tested for both packages.

## Residual risk

- Server-sent text (system messages, push notification bodies, error strings) is still Chinese.
- Machine-generated keys are not semantic; the catalogs carry the text side by side, and
  `scripts/i18n/extract.ts` documents the scheme.
- Date formats inside messages are slot-based ("{0}/{1}"), not full `Intl.DateTimeFormat`.
