## Decisions

- 2026-10-01 Fixed the cleared selection in `packages/ui/src/primitives/ContextMenu.{css,tsx}`
  (outside the card's paths) instead of snapshotting the selection in `features/message`, because
  the bug is the UI rule itself: its comment says "while a long press is being evaluated", but the
  selector disabled `user-select` whenever any menu was open, and Chrome clears a selection the
  moment `user-select: none` covers it. A workaround in the message feature would have left every
  other right-click menu in the app destroying selections.
- 2026-10-01 Kept `user-select: none` for a touch-opened menu (`data-tg-touch-open`), not only while
  holding, because the long-press timer turns `holding` off in the same render the menu opens; with
  selection re-enabled under the finger the native long-press selection/callout can appear.
- 2026-10-01 First-reaction burst uses a short-lived note (`features/message/reactionIntent.ts`,
  3 s window) written when the viewer ADDS a reaction, read on chip mount. Reading does not consume
  the note because React may run a state initializer twice (StrictMode); a remount inside 3 s
  bursting again is harmless. History chips (no note) still never burst, as TG-411 intended.
- 2026-10-01 The E2E tolerates exactly one known 403 (`/audit-events`, see Residual risk) so the
  script can exit 0; any other ≥400 response or page error still fails it.
- 2026-10-01 Walked against a server started with a copy of `chat-room.toml` that has
  `[redis] enabled = false`. With the repo default (Redis on) and this machine's Redis slow under
  five parallel agents, every session lookup stalled ~2.5 s and the first walk failed 14 of 17
  steps on timeouts — an environment effect, not product behaviour (see Residual risk).

## Residual risk

- **Out of scope, reported**: «操作日志» (`chatTasks/AuditLogEntry.tsx`, mounted for every group
  member by `chatInfo/ChatInfoPanel.tsx:98`) probes `GET /api/chats/:id/audit-events`; every
  non-manager gets a 403 and a console error. Same class of problem TG-905 fixed for the admin page.
- **Environment, reported**: the committed `chat-room.toml` enables Redis; when Redis is slow the
  session-cache read times out (~2.5 s) on every request instead of failing fast, which made the UI
  look frozen. Separately, with `[ai] enabled = false` the knowledge indexing worker still calls the
  embeddings endpoint and retries 401s in a loop (log noise, wasted requests). Neither is in this
  card's paths.
- Silent send: the browser walk proves delivery; that the recipient gets no notification is covered
  only by TG-404's server tests. Auto-delete expiry (minimum 1 day) is likewise covered by TG-405's
  server tests, not by this walk.
- The first-reaction burst relies on a 3 s window; on a very slow server round-trip (> 3 s) the
  first reaction lands flat, as before this fix.
