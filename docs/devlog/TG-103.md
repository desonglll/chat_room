## Frozen interface

Entry point: `packages/web/src/features/message/index.ts`.

```ts
// types.ts
type GroupPosition = 'single' | 'first' | 'middle' | 'last'
interface MessageRenderContext {            // structurally identical to TG-101's seam
  groupPosition: GroupPosition; isOutgoing: boolean; showAvatar: boolean
  showSenderName: boolean; highlighted: boolean; selected: boolean
}
interface MessageActions {                  // bound per message; every member optional
  onReply?(); onEdit?(); onDelete?(); onForward?(); onReact?(emoji: string); onPin?()
  onCopy?(); onSelect?(); onOpenMedia?(attachmentId: string); onJumpTo?(messageId: string)
}
type DeliveryStatus = 'sending' | 'sent' | 'read' | 'failed'
interface MessageBubbleProps {
  message: DisplayMessage                   // @tg/core: broadcast | system | upload
  ctx: MessageRenderContext
  actions?: MessageActions
  viewerId?: string                         // marks the viewer's reaction chips as chosen
  delivery?: DeliveryStatus                 // 'read' comes from read receipts; else message.delivery_state
  selectionMode?: boolean                   // list-wide: checkbox on every row, click = onSelect
  reserveAvatar?: boolean                   // keep the avatar column on rows without an avatar (default = showAvatar)
}
function MessageBubble(props: MessageBubbleProps): JSX.Element
```

- An absent action hides its menu row / button — that is how permissions reach the bubble.
- System rows (`type: 'system'`) render as a centred service pill; upload rows as an upload placeholder.
- The row owns the vertical rhythm (`--tg-bubble-gap` inside a group, `--tg-bubble-gap-group` on
  `first`/`single`). **TG-101's list must not add its own gap between rows.**

Content registry (`content/registry.ts`, app instance in `content/messageContent.ts`):

```ts
registerMessageContent(kind: string, Component: ComponentType<MessageContentProps>, options?: {
  match?(m: BroadcastMessage): boolean      // default: (m as any).kind === kind
  frame?: 'bubble' | 'media' | 'bare' | ((m) => ...)          // default 'bubble'
  metaPlacement?: 'inline' | 'overlay' | ((m) => ...)         // default 'inline'
  leadingMedia?: boolean                    // content starts with a full-bleed medium
  priority?: number                         // higher wins; ties -> later registration
}): () => void                              // undo
interface MessageContentProps { message; ctx; actions; metaSpacer: ReactNode }
```

A content that ends in text MUST render `metaSpacer` as the last inline node of that text
(use the exported `MessageText`). Built-ins: `deleted` (100), `image`/`video` (20), `file` (10), `text` (0, catch-all).

CSS: `features/message/message.css`, imported once from `src/styles/index.css`. Private
variables are `--tg-msg-*`; only semantic tokens are read.

## Decisions

- 2026-10-01 Timestamp no-overlap uses an invisible inline clone (`MetaSpacer`) of the absolutely
  positioned meta, rendered from the same `metaParts` in the same CSS box rules, instead of a
  fixed `padding-right`, because a fixed pad is wrong whenever the meta width changes (edited
  marker, ticks, 12/24h) and wastes a line when the last line is short.
- 2026-10-01 Tail is a separate SVG outside the body instead of a pseudo-element on the body,
  because the body needs `overflow: hidden` to clip full-bleed media to the corner radii and that
  would clip a pseudo tail. The tail is filled with the flat `--tg-bubble-in/out` (semantic.css says
  the fill may be a gradient).
- 2026-10-01 Corner/tail/frame/meta decisions live in pure `bubbleLayout.ts` rather than CSS
  combinators, because the combinations (group × side × media × decorations) are what the card
  asks to be tested, and `bun test` has no DOM.
- 2026-10-01 Borderless media only when nothing else is in the bubble; a name, forward header, quote
  or reaction row turns it into a filled bubble with the medium full-bleed (tweb behaviour). Borderless
  media has no tail and keeps the full radius on the tail corner (semantic.css rule).
- 2026-10-01 With reactions, the meta moves to the end of the reaction row (Telegram), so the spacer is
  passed to the reaction row and not the content.
- 2026-10-01 Text is plain + http(s) auto-link (`linkify.ts`), not markdown, because the markdown engine's
  block HTML cannot host the inline spacer without string surgery on sanitized HTML, and the current
  React client already renders plain text (no regression). A markdown kind can override `text` via the
  registry later (TG-104 owns formatting).
- 2026-10-01 Actions are bound per message (as the lead specified: `onReact(emoji)`, `onOpenMedia(id)`),
  and permissions are expressed by leaving callbacks undefined, instead of a separate capabilities prop.
- 2026-10-01 Added four optional props beyond the seam (`viewerId`, `delivery`, `selectionMode`,
  `reserveAvatar`) instead of widening `MessageRenderContext`, because the seam type is frozen with TG-101
  and those facts are list-wide or come from other streams (read receipts).
- 2026-10-01 SVG attachments render as a file card, never inline, because `image/svg+xml` is script-capable.
- 2026-10-01 Fixture photos are generated PNG data URIs (not inline SVG) so the fixture file carries no
  colour literal and passes the token-discipline scan honestly.
- 2026-10-01 Dev fixture page is served by Bun's HTML dev server (same pattern as `@tg/ui` docs) instead of
  a router route, so it never enters the shipped bundle and needs no hotspot edit.

## Residual risk

- Attachments carry no width/height on the wire, so an image row changes height when it loads; TG-101's
  virtual list must tolerate dynamic heights (react-virtuoso does), but the scroll anchor may nudge.
- Corners and tail use physical left/right; an RTL document would need mirrored rules.
- Album (grouped media) comparison from the acceptance line is not possible yet: there is no album
  wire type; TG-4xx albums should register a `bare`/`media` kind through the registry.
- Screenshots were compared against Telegram Web by eye only, not pixel-diffed.
