## Map provider decision (D-010, confirmed by the user 2026-09-30)

- **Leaflet 1.9.4** renders maps in the browser (new dependency in `packages/web`, with
  `@types/leaflet`; loaded lazily with its stylesheet, so it is not in the main bundle).
- **Tiles are configurable**: `[map] tile_url` / `attribution` (env `CHAT_ROOM_MAP_TILE_URL`,
  `CHAT_ROOM_MAP_ATTRIBUTION`), served to clients in `GET /api/config` as `map_tile_url` /
  `map_attribution`. Default: OpenStreetMap's public tiles; a privacy-sensitive deployment points
  it at a self-hosted tile server (an http(s) URL or a same-origin path with `{z}/{x}/{y}`).
- No geocoding service is called (no address lookup): nothing about a location leaves the
  deployment except the tile requests the viewer's own browser makes.

## Frozen interface

- `POST /api/chats/{id}/location-messages {latitude, longitude, accuracy_m?, heading?, title?,
  address?, live_seconds? (60–86400), reply_to?, topic_id?}` → 201 `StoredMessage` with
  `media_kind: "location"` and `location`. Post gate: `message.send` + `resolve_post_topic`.
- `PUT /api/chats/{id}/live-locations/{message_id} {latitude, longitude, accuracy_m?, heading?}`
  → 200 `MessageLocation` + `location_updated` frame; sender only (404 otherwise); 409 once ended.
- `DELETE /api/chats/{id}/live-locations/{message_id}` → stop now (the last point stays).
- `GET /api/chats/{id}/live-locations` → `LiveLocationEntry[]` being shared now (read gate).
- `StoredMessage.location` / broadcast `location`; frame `location_updated {message_id, location}`.

## Decisions

- **No trail**: `message_locations` holds one row per message with only the latest point; a live
  update overwrites it. After `live_until` (or a stop, which sets `live_until` to now) the server
  refuses points, so a finished share cannot be followed or replayed.
- Privacy notice in the share dialog states who sees it, how precise (± metres), and the no-trail
  rule; «模糊位置» rounds to two decimals (~1 km) client-side before anything is sent, for static
  and live shares alike.
- The browser sends live points at most every 15 s via `watchPosition`, stops itself at
  `live_until`, and stops on any 404/409 (ended elsewhere).
- Merged view: the location sheet shows this location plus every live location in the chat.
