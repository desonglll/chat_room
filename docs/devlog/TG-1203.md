## Frozen interface

- `PATCH /api/chats/:id/members/:user_id` — permission per action is now
  `approve|reject → members.review`, `remove → members.remove`, **`ban|unban → members.ban`**
  (was `members.remove`). `remove`/`ban` of an **administrator** by anyone but the owner →
  **409** (was allowed). Owner targets and self-removal stay 409. No body/shape change.
- `ChatAdminEntry` gains `managerExtra?: (view: ChatPermissionsView) => ReactNode`, rendered after

## Decisions

- 2026-10-01 Ban requires `members.ban`, not `members.remove`, because the registry labels
  `members.ban` «封禁与限制成员» (Telegram's "Ban users") and the restriction endpoint already uses
  it; an admin granted exactly that right could restrict but not ban.
- 2026-10-01 Only the owner removes/bans an administrator (409 otherwise), matching the
  restriction endpoint's existing «dismiss first, then restrict» rule. Telegram also lets the
  promoting admin do it; we do not track the promoter for removal, and the stricter rule is safe.
- 2026-10-01 Restricted members get a bar via `ChannelFooter`/`useChannelPublisher` instead of an
  edit in `features/chat/ChatPane.tsx`, because ChatPane is outside this card and already routes
  "may not write" to that footer. The footer's name is now slightly broad; documented in its header.
- 2026-10-01 The banned list reads `GET /api/chats/:id/members` (needs `members.review`) and
  filters `status === 'banned'` — no new endpoint, no core change. An admin with `members.ban`
  but not `members.review` sees «读取失败» there; acceptable for now (see Residual risk).
- 2026-10-01 The audit log mounts through `ChatAdminEntry.managerExtra` so the info panel does not
  issue a second `GET /permissions`; it moved from below the shared media to right under the
  admin entry (Telegram keeps «最近操作» inside the admin area too).
- 2026-10-01 Did NOT drop the global unique index on active chat titles (`chats_title_active_idx`)
  even though Telegram allows duplicate names: `client join --room-name` and the explicit test
  `integration_test::reject_duplicate_room_name` rely on it. Lead decision (see Residual risk).
- 2026-10-01 Walkthrough runs against the built bundle via `vite preview` + proxy, not
  `vite dev`: dev mode serves hundreds of unbundled modules and Chromium hit
  `net::ERR_INSUFFICIENT_RESOURCES` with five pages open (blank pages, not a product bug).

## Residual risk

- Chat titles are globally unique among active chats (409 «已有同名会话»); Telegram allows
  duplicates. Changing it needs a forward migration dropping `chats_title_active_idx` on both
  adapters plus a rule for `client join --room-name` ambiguity — a lead decision.
- The banned list needs `members.review`; an admin holding only `members.ban` bans fine but sees
  «读取失败» on «已封禁的用户».
- A restriction applied while the member has the chat open is not pushed to their composer; the
  bar appears on the next open (server still refuses the sends).
- Admin removal: Telegram lets the promoting admin remove admins they appointed; here only the owner.
