## Frozen interface

- New server frame `{"type":"pins_changed","message_id":uuid,"pinned":bool}`, broadcast to the chat
  after a successful `POST`/`DELETE /api/chats/:id/pins/:message_id`. Additive; older clients drop
  unknown frames (frameCodec contract).
- `@tg/ui` `Menu` / `ContextMenu` gain `header?: (close) => ReactNode` (generic; no business concept).
- `MessageActions.onUnpin`.

## Decisions

- 2026-10-01 **Audit correction**: TG-804's P1-1 ("no right-click menu") was wrong — `MessageRow`
  wraps every bubble in `ContextMenu`; the walkthrough right-clicked empty row space. Re-verified in
  the browser before building. What was really missing: the quick-reaction strip at the top of the
  menu, an icon for «保存到收藏夹», and the hover bar staying visible under the open menu — fixed.
- 2026-10-01 Pinned bar refresh is a re-read on a `pins_changed` frame rather than a frame carrying
  the pin list: one source of truth (`GET /pins` with its read-time authorization), tiny frame.
- 2026-10-01 Bar shows newest pin first; a click jumps (`?message=` route the list already honours)
  and moves to the next older pin, wrapping; up to 4 track segments like Telegram. Not shown inside
  forum topics (their header is different).
- 2026-10-01 «取消置顶» replaces «置顶» in the menu for an already pinned message; the pinned-id set
  is a dep of the row renderer so labels update on change.
