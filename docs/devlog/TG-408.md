## Frozen interface

- WS `message` frame: optional `no_link_preview: true` (the sender dismissed the card).
- `StoredMessage.link_preview` / broadcast `link_preview` `{url, site_name, title, description,
  image_url?}`; frame `link_preview_updated {message_id, preview | null}` (null = hidden).
- `GET /api/link-preview?url=` (authenticated) → 200 card / 204 none — the composer's preview.
- `DELETE /api/chats/{id}/messages/{message_id}/link-preview` → 204; sender only (404 otherwise).
- Config `[link_preview] enabled` (env `CHAT_ROOM_LINK_PREVIEW_ENABLED`), and
  `unsafe_allow_sockets` (TOML only, exact `ip:port`, **test fixtures only**).

## Security review (SSRF) — integration lead, 2026-10-01

Threat: a member posts a link so that the server fetches an internal resource (loopback admin
ports, cloud metadata at 169.254.169.254, RFC 1918 services) and leaks it through the card, or
uses the server to probe the internal network.

| Control | Where | Test |
| --- | --- | --- |
| Only `http`/`https`; no credentials in the URL; ports 80/443/8080/8443 only | `ssrf::check_url` | unit + `the_task_card_ssrf_cases_are_refused` (`file://`, `gopher://`, `:6379`) |
| IP literals judged before any socket: loopback, RFC 1918, link-local/metadata, CGNAT, 0/8, multicast, broadcast, documentation, benchmarking, 240/4, ::1, ::, fc00::/7, fe80::/10, fec0::/10, 2001:db8::/32, IPv4-mapped/compatible, NAT64 and 6to4 embeddings; decimal/hex IPv4 spellings normalised by the URL parser first | `ssrf::is_public_ip` | unit (21 addresses) + `127.0.0.1`, `169.254.169.254`, `[::ffff:127.0.0.1]`, `2130706433` |
| Host names resolved by us; **every** answer must be public (mixed answers refused) | `ssrf::pick_address` | `mixed.test` case |
| The checked address is pinned for the connection (`ClientBuilder::resolve`), so DNS rebinding between check and connect cannot redirect the socket | `fetch.rs` | rebinding test: resolver called exactly once per hop |
| Redirects followed by hand (max 3), each hop re-checked and re-resolved | `fetch.rs` | redirect to metadata, to loopback, to a rebinding host, and a loop |
| No proxy from the environment (`no_proxy()`); 5 s overall deadline; body read capped at 256 KiB; only `text/html`/`application/xhtml+xml` parsed | `fetch.rs` | JSON page refused |
| At most 4 fetches in flight server-wide; failures cached 10 min, successes 24 h (no amplification by repeating a link) | `mod.rs` | — |
| The server never fetches the `og:image`; it is only kept if absolute http(s) and is loaded by the viewer's browser with `referrerpolicy=no-referrer`; card links open with `noopener noreferrer` | `parse.rs`, `LinkPreviewCard` | parse unit test (`javascript:` image dropped) |
| Fetch runs after the message is stored and delivered; failures never block or fail a send | `build_link_card` | slow-site test: message delivered < 1 s while the site takes 3 s |

"Independent restricted egress" from the task card: the fetcher uses no ambient proxy and holds
its own policy; deployments that want network-level isolation should additionally firewall
the server's outbound traffic (documented residual below). `unsafe_allow_sockets` exists only so
the test suite can reach its local fixture; it exempts exact sockets, never ranges.

Verdict: **approved for merge.**

## Decisions

- Only the first http(s) link of a text message gets a card (Telegram). Cards are a projection:
  `link_previews` (cache by URL) + `message_link_previews` (which URL, hidden flag).
- The composer shows the draft's card (debounced 500 ms, fetched by the server); ✕ sends the
  message with `no_link_preview`. A sent message's card can be removed by its sender (menu
  «移除链接预览»), for everyone, via a `link_preview_updated` frame with `null`.

## Residual risk

- A public host that serves different content to the server than to users can still show a
  misleading card (inherent to previews; the card shows the site name).
- Network-level egress filtering is recommended in production in addition to the in-process
  policy (defence in depth against a future bug in the policy).
- Only text sent over the WebSocket gets cards; HTTP-sent kinds (captions, scheduled sends) do not.
