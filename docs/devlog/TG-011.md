## Frozen interface

TG-012 (login shell), TG-101/102/103 (M1) and TG-008 (drafts wiring) build on this section.
Everything here mirrors contracts that are already frozen elsewhere; this package adds no wire
contract of its own.

### 1. Package layout and subpath exports (architecture.md §2)

`@tg/core` exports five barrels and nothing else: `./types`, `./api`, `./realtime`,
`./stores`, `./domain` (plus the root barrel re-exporting all five). One domain, one file.
`packages/core/src/api/drafts.ts` and `packages/core/src/domain/draft*` are **reserved for
TG-008** — this task neither creates nor references them.

### 2. `types/` — mirrors of the CURRENT Rust wire contract

- `types/chat.ts` — the **canonical** Chat descriptor exactly as `GET /api/chats/:id`
  serialises `src/chats/models.rs::Chat`: `title` (never `name`; the deprecated spelling is
  alias-only and this package does not model it), `membership_status`/`membership_role`
  *omitted* (not null) when absent, `password_hash`/`access_hash` never present.
  `ChatType = 'private' | 'group' | 'supergroup' | 'channel'`. `ChatMembership`, `ChatMember`
  as TG-004/TG-007 froze them.
- `types/message.ts` — `StoredMessage` (REST, `room_id` spelling frozen by D-003 /
  TG-004 "Frozen non-rename 1"), `Attachment`, `ReplyPreview`, `ForwardedFrom`,
  `MessageReaction`, `ReadReceipt`, `ChatFilePage`, `ForwardResult`.
- `types/user.ts` — `User`, `UserSummary`, `AuthSession`, `PublicConfig`.
- `types/realtime.ts` — every WS frame from docs/devlog/TG-007.md's frozen interface,
  shapes pinned against `tests/ws_frame_snapshot_legacy_test.rs` and
  `tests/ws_frame_snapshot_extension_test.rs`: the ten `TypingAction` values,
  `UserStatus` tiers (`online`/`offline{last_seen}`/`recently`/`within_week`/`within_month`/
  `long_ago`/`empty`), `auth_ok` with `room_name` (frozen spelling) and `statuses`, the six
  skeleton frames (`chat_updated`, `member_updated`, `topic_updated`,
  `message_views_updated`, `poll_updated`, `draft_updated`), and the client→server frames
  (`join`, `auth`, `message`, `edit`, `read`, `recall`, `reaction`, `poke`, `typing`).
  `DraftUpdatedFrame` is `{user_id, text, reply_to_message_id, topic_id, updated_at}` —
  TG-008's frozen shape, typed here so composerStore can consume it without importing
  TG-008's modules.
- `types/platform.ts` — the injected platform capabilities (see §4).

### 3. `realtime/` — WS client

- `frameCodec.ts` — `parseServerFrame(raw)` returns a typed frame or `null` (unknown frame
  *type* → `null`, mirroring the server's ignore rule; unknown `typing.action` string →
  `'typing'`, the degradation TG-007 REQUIRES of clients; missing `action` → `'typing'`).
  `encodeClientFrame(frame)` → JSON string.
- `backoff.ts` — `reconnectDelayMs(attempt)` = `min(500 * 2^attempt, 5000)`, the frozen Vue
  client's schedule, kept so reconnect behaviour does not regress during the rewrite.
- `chatSocket.ts` — `createChatSocket(options)`: join/auth handshake (`auth` when a password
  is supplied, else `join`), per-frame-type subscription management (`on(type, fn)` →
  unsubscribe, plus `onAnyFrame`/`onStatus`), reconnect with the backoff above via the
  injected clock, and missed-message catch-up: the client tracks the newest broadcast
  cursor `{timestamp, messageId}` and after the `history_complete` of a *re*connect calls
  the injected `fetchMissed(cursor)` and re-emits the returned messages as `broadcast`
  frames (dedup stays in `domain/chatIncoming.mergeIncomingBroadcast`, which is
  message_id-idempotent). Sockets and timers are injected; core never touches a global.

### 4. Injected platform capabilities (`types/platform.ts`)

Hosts (packages/web now, React Native later) implement and inject these; core only defines
them. Names match the card: `createStorage()` → `CoreStorage` (`getItem`/`setItem`/
`removeItem`, string-valued), `createWebSocket()` → `CoreSocketFactory = (url) =>
CoreSocket` (`send`, `close`, `onopen`/`onmessage`/`onclose`/`onerror` setters, the exact
subset of the WHATWG surface the old client used), `createFileReader()` →
`CoreFileReader = (source: FileChunkSource)` with `FileChunkSource = { size,
readChunk(start, end): Promise<Uint8Array> }`, `createClock()` → `CoreClock`
(`now()`, `setTimeout()`, `clearTimeout()`). `domain/fileHash.hashFile` additionally takes
a `Sha256StreamFactory` (`create() → { update(bytes); digestHex() }`) so the digest
primitive is host-supplied and core stays dependency-free (see Decisions).

### 5. `stores/` — 9 zustand VANILLA stores, one domain one file

`authStore` `chatListStore` `messageStore` `composerStore` `presenceStore` `stickerStore`
`mediaStore` `settingsStore` `uiStore` — exactly the architecture.md §2 listing. Each file
exports `createXxxStore()` (a fresh `zustand/vanilla` store, the testable form) and a
module-level `xxxStore` singleton for the app. `composerStore`'s per-chat draft slice is
`{text, replyToMessageId, topicId, updatedAt}` and `applyDraftUpdated(chatId, frame)`
consumes the frozen `draft_updated` frame verbatim; the api call itself is TG-008's.

### 6. `api/` — HTTP clients, canonical dialect only

`createApiClient({fetchImpl, baseUrl?})` + per-domain modules (`auth`, `config`, `chats`,
`messages`, `search`). All chat-scoped paths use `/api/chats/*` (TG-004 §5 canonical);
requests send `title`, never `name`. Room-password header keeps its frozen spelling
`x-room-password`. Errors surface as `ApiError{status, path}` — human copy is the UI's job
(the old client's hardcoded Chinese strings deliberately do not migrate; see Decisions).

## Decisions

- 2026-09-30 **`markdown` migrates as a policy module with injected `parse`/`sanitize`, not
  as a wrapper over `marked`+`dompurify`.** The old module is 11 lines of configuration
  around those two libraries; `dompurify` requires a DOM (its sanitizer instantiates against
  a Window) so it can never live inside the no-DOM boundary, and adding either to
  `packages/core/package.json` is outside this task's dependency grant (zustand only).
  What is actually frozen — `breaks:true, gfm:true`, sanitize-after-parse with the
  `USE_PROFILES:{html:true}` profile — migrates as exported constants plus
  `createMarkdownRenderer({parse, sanitize})`; packages/web injects the real libraries.
- 2026-09-30 **`fileHash` migrates with an injected SHA-256 stream and chunk reader instead
  of `@noble/hashes`.** Same grant reasoning: the only pre-approved new core dependency is
  zustand. The logic the card wants kept — 4 MiB chunking, per-chunk progress callbacks,
  abort between chunks, hex digest — is exactly what migrates; the digest primitive becomes
  the `Sha256StreamFactory` capability. The test verifies against the standard `abc` vector
  and a multi-chunk case using Bun's own hasher as the injected implementation, so the
  digest is still checked against a real SHA-256, not a mock.
- 2026-09-30 **API error copy does not migrate.** The old `api.ts` throws hardcoded Chinese
  strings per status; that is presentation, and freezing it into `core` would force RN and
  web to share UI copy. `ApiError` carries `status` + `path` + the response body's `error`
  field when present; mapping to copy is TG-012+'s job.
- 2026-09-30 **`randomUuid` keeps its RFC-4122-v4 fallback but defaults its source to
  `globalThis.crypto` instead of `window.crypto`.** Web Crypto is a standards-level global
  (present in browsers, bun, and RN via polyfill), same category as `fetch`; `window` is
  banned. The source stays injectable for hosts without the global.
- 2026-09-30 **`textFrameBatch` loses its `requestAnimationFrame` default arguments; the
  scheduler is now a required parameter.** rAF passes the lexical boundary scan (it is not
  one of the four banned tokens) but does not exist in bun or RN — a default that crashes
  off-DOM is worse than no default. Hosts pass rAF (web) or the injected clock.
- 2026-09-30 **`messageDeepLink` migrates with the route name as a parameter defaulting to
  `'chat'`** (old hardcoded `'room'`). The old spelling described the Vue router's route
  record, not a server contract; the new React router (TG-012) names the record `chat`. The
  old behaviour is reachable by passing `'room'`, and the migrated test pins both.
- 2026-09-30 **`searchPattern` is implemented as the client-side mirror of
  `src/messages/search_pattern.rs::like_pattern`** — no `web/src` module carries that name;
  the corresponding logic in the repository is the server's LIKE-escape (`\`, `%`, `_`
  escaped, wrapped in `%…%`), which the client needs to predict match behaviour (highlight,
  local pre-filter) consistently with server search. The migrated test pins the exact Rust
  test vector (`50%_done\ok` → `%50\%\_done\\ok%`) plus a client-side case-insensitive
  predicate/highlighter derived from it.
- 2026-09-30 **Client-view message types (`DisplayMessage`, `UploadMessage`,
  `delivery_state`, `motion`) live in `domain/messageView.ts`, not `types/`.** `types/` is
  reserved for mirrors of the Rust wire contract; `delivery_state`/`motion` exist only in
  the client. The wire `broadcast` frame type in `types/realtime.ts` is extended by the view
  layer (`BroadcastMessage = BroadcastFrame & {delivery_state?, motion?}`), so the wire
  mirror stays exact. Optional view fields are declared `?: X | undefined` because the
  workspace compiles with `exactOptionalPropertyTypes`.
- 2026-09-30 **Abort is signalled with `Error{name:'AbortError'}`, not `DOMException`.**
  `DOMException` is not guaranteed off-DOM (Hermes); the `name` property is what callers
  actually branch on.
- 2026-09-30 **The WS client re-emits catch-up results as ordinary `broadcast` frames, not
  through a parallel delivery channel.** Consumers then need exactly one merge path
  (`mergeIncomingBroadcast`, idempotent on `message_id`), and the server's own reconnect
  history replay and the REST catch-up converge on identical handling. The alternative — a
  separate event kind — would force every subscriber to duplicate its merge logic. A failed
  catch-up fetch is swallowed (the next reconnect or the server replay gets another chance)
  rather than allowed to tear down a healthy socket.
- 2026-09-30 **`auth_fail` is terminal for the WS client: no reconnect is scheduled.**
  Retrying the same credentials cannot succeed and would hammer the server's auth path; the
  old client behaved the same way (`status: failed`, reconnect disabled).
- 2026-09-30 **`zustand@5.0.8` added to `packages/core` only** (pre-approved by the lead;
  architecture.md §2 mandates the vanilla form). `bun install` regenerated the root
  `bun.lock` — that lockfile diff is expected and contains only the zustand entry.
- 2026-09-30 **Store singletons are exported alongside factories.** Factories
  (`createAuthStore()`) keep tests isolated; the module-level singleton is what
  `packages/web` subscribes to with `useStore`. Both come from the same closure so there is
  one initial-state definition per store.
- 2026-09-30 **`bun.lock` edited via `bun install` although §3.1 lists it as
  integration-lead-owned** — explicitly granted on this task's card ("update the root
  bun.lock (bun install) — pre-approved"). Root `package.json` and `packages/*/package.json`
  other than core's were not touched.

## Residual risk

- **The WS client is verified against a fake socket only.** No live server drive in this
  task (bun-only build scope); TG-012's acceptance run (register → chat → message → second
  browser) is the end-to-end proof. The frame shapes themselves are pinned byte-for-byte
  against the Rust snapshot fixtures, so the risk is confined to connection lifecycle
  against real network timing.
- **Store skeletons encode shape, not policy.** e.g. `chatListStore` does not yet sort by
  `last_activity_at` (the conversation row is alias-dialect until M1 models it) and
  `presenceStore` expiry needs the host to drive `expireTyping(now)`.
- **`types/` optionality mirrors serde behaviour observed in the snapshot tests**, e.g.
  broadcast nullable fields present-as-null vs `client_message_id` omitted-when-absent. If a
  later Rust change flips a `skip_serializing_if`, nothing in bun-land fails automatically —
  the Rust snapshot tests are the tripwire, and `types/realtime.ts` documents each such
  field inline.
- **`bun.lock` diff.** Regenerated by `bun install` for zustand; if the lead's integration
  branch also touches the lockfile (TG-008 has no grant, so unlikely), regenerate rather
  than merge textually.
