## Decisions

- 2026-10-01 Requests carrying a `Range` header bypass the service worker, and `cacheFirst` stores only status 200, rather than slicing a cached full body for range requests — because `<audio>`/`<video>` always ask for ranges, the server answers 206, and `cache.put` rejects a 206, which rejected the whole `respondWith` (`net::ERR_FAILED`). Slicing would keep voice playable offline but is new machinery for a P3 offline case; playback online is the defect.
- 2026-10-01 Fixed album order in the media viewer locally (`mediaItem.compareItems` breaks millisecond ties on the sub-millisecond RFC 3339 digits) rather than in core `compareInstants`, because core is outside this card. `POST /albums` writes items 1 µs apart and `Date.parse` drops that; the old UUID tie-break shuffled album pages. Core `compareInstants` has the same millisecond limit — recorded below for the lead.
- 2026-10-01 Did not wire custom-emoji input into the composer: it needs `features/composer/**` (TG-1201's), `features/chat/chatSession.ts` and core `messageStore` (lead). The E2E sends the entity message over the chat socket exactly as the composer would, which verifies the display path end to end. Integration patch below.
- 2026-10-01 The walkthrough used `vite preview` (production bundle, real service worker) proxied to the server, not `vite` dev: dev mode has no SW (so it hides the SW defect) and its unbundled modules ran the 14 GB machine out of memory (renderer "Target crashed").
