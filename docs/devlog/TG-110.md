## Frozen interface

Settings registry — `packages/web/src/features/settings/shell` (barrel `index.ts`):

```ts
type SettingsSectionId = 'account' | 'notifications' | 'privacy' | 'storage' | 'appearance'
                       | 'folders' | 'language' | 'devices'
interface SettingsPageProps { onBack(): void; onClose(): void }
interface SettingsPageRegistration {
  id: string                    // unique, e.g. 'appearance.theme'
  section: SettingsSectionId
  title: string
  icon?: ReactNode              // row glyph when the section lists several pages
  component: ComponentType<SettingsPageProps>   // rendered in Suspense: lazy() welcome
  order?: number                // default 100, ascending
  ownsHeader?: boolean          // page draws its own header + back; shell draws none
}
registerSettingsPage(page): () => void          // idempotent by id; returns unregister
openSettings(view?: { kind: 'section'; id } | { kind: 'page'; id }): void
```

How an M5 task plugs in (no shell edit): create `features/<x>/register.ts` calling
`registerSettingsPage({ id, section, title, component: lazy(() => import('./XPage')) })` and add one
side-effect import line to `src/main.tsx` (like `features/poll/register`). A section with 0 pages shows
«即将推出»; with 1 page, opening the section opens the page; with ≥2, the section lists them.

Section owners: account TG-110/TG-511 (avatar page goes beside `account.profile`), notifications
TG-508, privacy TG-505/TG-506 (mounted), storage TG-509, appearance TG-507, folders TG-501,
language TG-510, devices TG-110.

Core: `listDeviceSessions(client, token)`, `revokeDeviceSession(client, token, id)` (404 = already gone,
409 = current session → throws), `revokeOtherDeviceSessions(client, token)`, type `DeviceSession`.

Chat session: `ChatSessionStores.poll?: PollStore` — `poll_updated` frames go to it via `applyPollFrame`.

Server: `AppState::edit_message` answers `None` for a message that carries a poll (same as an edit of
someone else's message: no `message_edited` broadcast, nothing stored).

## Decisions

- 2026-10-01 Poll frames feed TG-406's `pollStore` (injected as `stores.poll`), not `messageStore`,
  because the bubble already merges `message.poll` with `pollStore` by revision (`effectivePoll`);
  a second write into the timeline would duplicate that merge in core, which has no `mergePollState`.
- 2026-10-01 Poll edit is refused in SQL (`AND NOT EXISTS (SELECT 1 FROM polls …)` in the edit's
  UPDATE) rather than a pre-check, so there is no read-then-write race and both adapters share one
  statement; the WS handler already ignores `Ok(None)`.
- 2026-10-01 The AttachMenu owns the lazy `PollCreateDialog` (state + Suspense inside AttachMenu),
  so the composer edit is a single `chatId` prop; TG-303 is working in the composer.
- 2026-10-01 Radio fix is stacking, not markup: `z-index: 1` on the invisible input and
  `pointer-events: none` on the ring. Checkbox does not need it (its box is not positioned, so the
  absolutely positioned input already paints above it).
- 2026-10-01 Settings panel lives inside `.tg-shell__sidebar` (absolute, `max(100%, column width)`,
  capped at 100vw): it covers the column on desktop, the screen on mobile, and stays usable over a
  collapsed column. It slides in from the left edge (Telegram's drawer direction) so the moving panel
  never paints over the conversation; pushed views slide inside the clipped panel. Reduced motion: fades.
- 2026-10-01 The whole panel (and every page) is lazy: `SettingsHost` imports `SettingsPanel` on first
  open; `builtinPages.ts` registers from inside that chunk. Boot bundle only carries the registry and
  the navigation store.
- 2026-10-01 Added an eighth section «聊天文件夹» (TG-501's slot) beyond the lead's list, because
  Telegram lists Chat Folders at the settings root and TG-501 needs a place to register.
- 2026-10-01 Esc closes the panel only when focus is inside it (or on body) and no inner `@tg/ui`
  overlay consumed the key first (`defaultPrevented`), so Esc in the composer still cancels a reply.
- 2026-10-01 Device terminate uses an inline confirm row instead of a Modal: no extra layer inside a
  panel that itself listens for Esc, and focus stays in place.
- 2026-10-01 E2E steps for this task live in `test/e2e/batch2.steps.mjs`, imported by `m1-chat.e2e.mjs`,
  because adding them inline pushed the script past the 350-line limit.
