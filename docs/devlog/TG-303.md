## Decisions

- 2026-10-01 **Virtual list at row granularity, not IntersectionObserver-per-section.** TG-301's manager fetches and parses a sticker the moment its view attaches (`stickerManager.attach → prepare`), whatever its visibility, so every mounted cell costs a fetch + worker parse. The grid is fixed-geometry (header 32 px, cell 72 px), so layout is arithmetic (`panelLayout.ts`) and only the rows within viewport ± 144 px are mounted: 36 `.tg-sticker` views (24 cells + 12 rail thumbnails) for a 300-sticker library, constant while scrolling. The naive alternative mounted 300 and fetched/parsed all of them.
- 2026-10-01 **Rail ↔ grid sync is computed from the same layout** (`sectionAt(layout, scrollTop)`, rAF-throttled scroll listener), not from observers; rail clicks `scrollTo` the section's offset (instant under reduced motion). Section headers are `scroll-snap-align: start` with `scroll-snap-type: y proximity`, so flings settle on a set boundary without fighting slow scrolls.
- 2026-10-01 **Suggestions are local and clock-driven.** `suggestStickers` reads a memoised emoji → stickers `Map` built from the installed sets (same visibility as `GET /api/stickers/search`: non-archived installed sets, plus the viewer's favorites/recents), so a keystroke costs a Map lookup and no request. `suggestionController` shows the strip `SUGGESTION_DELAY_MS = 60` ms after the draft becomes one emoji (absorbs IME intermediate states such as 👩 → 👩‍💻) and hides it immediately otherwise. Measured: fake-clock unit test (≤ 200 ms asserted) and 62–67 ms in headless Chromium.
- 2026-10-01 `singleEmoji` is a Unicode-property regex (RI pairs, keycaps, tag sequences, ZWJ chains with FE0F and skin tones), not `Intl.Segmenter`, because it must also say "this grapheme is an emoji" and must work in core-style pure tests.
- 2026-10-01 **Press-and-hold preview for mouse and touch** (350 ms hold, 10 px slop), a pure state machine (`pressPreview.ts`) over the injected clock. While the preview is open, moving over other stickers switches it (this is the "hover" part of Telegram's preview); release closes it and swallows the click so it does not also send. Right click opens send / favorite / remove-from-recents / view-pack. One delegated set of listeners on the grid, none per cell.
- 2026-10-01 **Sticker send goes over HTTP** (`POST /api/chats/:id/sticker-messages` with a fresh `client_message_id`), and the 201 body is merged into `messageStore` at once; the WS echo of the same `message_id` is idempotent (`mergeIncomingBroadcast`). The reply bar is consumed (`controller.consumeReply()`); picking a suggestion also clears the emoji draft, as in Telegram. The server already records the sticker in recents; the client mirrors it with `pushRecent`.
- 2026-10-01 **Overlays live in the shell, not the composer popover.** The popover closes on any outside pointer, and a modal is "outside", so a set preview or the management page opened from the panel would unmount itself. `overlayStore.ts` + `<StickerOverlays>` (mounted beside `ChatOverlays`) host them; both are lazy chunks.
- 2026-10-01 **`StickerView` is a local format dispatcher** (TGS → `<AnimatedSticker>`, WebP → lazy `<img>`, WebM → muted looping `<video>` that does not autoplay under reduced motion) because TG-306's `<Sticker>` is being written in parallel inside `renderer/**`. When it lands, `StickerView.tsx` becomes a re-export; nothing else in the feature knows formats.
- 2026-10-01 The sticker message is recognised by `media_kind === 'sticker'` **or** the TGS MIME, because TG-302's forward path drops `media_kind`/`sticker_id` (TG-302 residual risk): a forwarded TGS sticker still renders as a sticker (without the "view pack" link).
- 2026-10-01 Search is local first (emoji → stickers; text → installed set titles/short names) plus a debounced `GET /api/sticker-sets/:name` when the query is shaped like a short name no installed set has, which is how an uninstalled pack is found and added. There is no server-side keyword → emoji search endpoint; not needed for this card.
- 2026-10-01 The library store resets on any token change (sign-out, account switch), subscribed once in `stickerLibrary()`.
- 2026-10-01 Web-side module names avoid case-only collisions (`overlayStore.ts`, `stickerMessageModel.ts`): bun's resolver on this host resolved `./stickerOverlays` to `StickerOverlays.tsx`, which also breaks on case-insensitive macOS volumes.
- 2026-10-01 The panel benchmark gates the **warm** open (the page has rendered the panel once over a tiny different library — code, fonts and styles warm, as in a running app — but has never seen the measured stickers). A cold first open of a fresh page takes ~70–90 ms in one task **with 5 stickers as with 300**: a Chrome trace shows 35 ms of first `Layout` over 67 objects (first CJK/medium-weight font fallback on this host) plus forced layout in the grid's measure; a second open of the same panel mounts in 5–9 ms. It is reported, not gated.

## Benchmark

`cd packages/web && node src/features/sticker/bench/measurePanel.mjs [--json f] [--shots dir]` — production build of `bench/index.html`, served by `vite preview`, headless Chromium (Playwright from `$PLAYWRIGHT_MODULE`, default `/tmp/pw/...`). 12 sets × 25 = **300 synthetic TGS stickers** from TG-301's `syntheticLottie` (24 layers, 512², 60 fps, 3 s), gzipped to blob URLs so fetch → inflate → parse run as in the app. Long tasks via a page-lifetime `PerformanceObserver`.

Run 2026-10-01, load average 3.3 (host shared with other agents):

| scenario | mount | first paint | mounted views | long tasks while settling (3 s) | settle fps | scroll top→bottom 3 s |
| --- | --- | --- | --- | --- | --- | --- |
| **virtual, warm (gated)** | 31.6 ms | 39.7 ms | 36 | **0** (TBT 0) | 59.5 | 59.6 fps, p95 16.7 ms, 0 long tasks, 36 mounted |
| virtual, cold (fresh page) | 91.8 ms | 106.9 ms | 36 | 1 × 92 ms (TBT 42) | 58.0 | 59.4 fps, 0 long tasks |
| naive (all 300 mounted), warm | 44.6 ms | 74.0 ms | 300 | 0 | 58.9 | 59.6 fps, 300 mounted |

Suggestion latency, keystroke (`input` event) → strip in the DOM, 5 emoji: 66.9, 63.2, 62.6, 61.8, 62.9 ms (max 66.9; gate 200).

Gates (`THRESHOLDS` in `measurePanel.mjs`): warm open — no long task at all, TBT 0, first paint ≤ 50 ms; scroll ≥ 50 fps with no long task > 100 ms; suggestion ≤ 200 ms. All PASS.
