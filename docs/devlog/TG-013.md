## Frozen interface

Other tasks (and the CI reading scripts a future task may add) may depend on this.

### 1. The service-availability contract for tests

For every test that needs an external service, one rule, no exceptions and no
probe-and-fall-back URLs:

| Env state | Behavior |
| --- | --- |
| env var unset | test **skips visibly**: exactly one marker line per skipped test on the real stderr |
| env var set, service reachable | test runs |
| env var set, service unreachable | test **panics** ("misconfigured" must never look like "not configured") |

Env vars: PostgreSQL `TEST_POSTGRES_ADMIN_URL` (admin URL with `CREATE DATABASE`
rights); Redis `TEST_REDIS_URL`, falling back to `CHAT_ROOM_REDIS_URL`. Local
defaults come from `docker-compose.local.yaml`:
`postgresql://chatroom:chatroom@127.0.0.1:52735/postgres` and
`redis://127.0.0.1:6379/`.

### 2. The marker line (greppable, frozen prefix)

```
SKIPPED: PostgreSQL not verified: <test_name> — <hint>
SKIPPED: Redis not verified: <test_name> — <hint>
```

The prefix up to and including the second `:` is frozen. Count a run's
unverified coverage with:

```sh
cargo test --all-targets --all-features 2>&1 | grep -c 'SKIPPED: PostgreSQL not verified'
```

### 3. The helper API — `tests/service_skip/mod.rs`

```rust
pub const POSTGRES_ENV: &str = "TEST_POSTGRES_ADMIN_URL";
pub fn emit_skip_marker(service: &str, test_name: &str, hint: &str);
pub fn postgres_admin_url_or_skip(test_name: &str) -> Option<String>;
pub async fn postgres_admin_pool_or_skip(test_name: &str) -> Option<(String, sqlx::PgPool)>;
pub fn redis_url_or_skip(test_name: &str) -> Option<String>;
```

Include from a top-level test binary with `mod service_skip;`, from a module in a
subdirectory with `#[path = "../service_skip/mod.rs"] mod service_skip;`.

### 4. Signature change in `tests/migration_support/mod.rs`

`postgres_admin_pool()` → `postgres_admin_pool(test_name: &str)`; it now
delegates to `service_skip` and the never-connecting fallback URL is gone.
`postgres_admin_url()` is removed. All callers updated in the same commit.

## Decisions

- 2026-09-30 Removed the fallback URL entirely instead of fixing its credentials,
  because a probe-and-fall-back makes "PostgreSQL absent" a network question; the
  card prefers this ("一个连不上的兜底比没有兜底更坏") and the lead's adapted
  acceptance defines "PostgreSQL absent" as exactly "env var unset".
- 2026-09-30 Markers are written straight to the stderr file descriptor
  (`std::io::stderr().write_all`), not via `eprintln!`, because libtest captures
  the `eprintln!` of a passing test and discards it — that capture is the actual
  mechanism of today's silence (the old code did print "skipping…"; nobody ever
  saw it). Direct fd writes bypass capture and appear in a plain `cargo test` run.
- 2026-09-30 One shared module `tests/service_skip/` instead of per-file helpers,
  because six files carried six diverging copies of the same match (four with
  wrong-credential fallbacks) and the defect survived precisely because each copy
  could rot alone. Named for its single responsibility (visible skipping for
  service-backed tests), not `utils`/`common`, per AGENTS.md.
- 2026-09-30 The module is declared where it is used (`mod service_skip;` in each
  top-level binary, `#[path]` in `migration_support/mod.rs` and
  `tests/integration/postgres.rs`) instead of adding it to `tests/support/mod.rs`,
  because `tests/support` is included by ~30 binaries TG-007 may touch and I only
  own skip logic; a new directory module has zero merge surface.
- 2026-09-30 `docker-compose.local.yaml`: no port change — the host port is
  already pinned (`127.0.0.1:${POSTGRES_PORT:-52735}:5432`), and removing the
  fallback removed the only hardcoded port in test code. Added comments mapping
  each service to its test env var so the compose file and the markers
  cross-reference each other. The hint string names the default URL; if
  `POSTGRES_PORT` is overridden the operator sets the env var anyway, so the
  hint cannot silently mislead a test (it is prose, not a connection target).
- 2026-09-30 Redis silent skips (2 tests: `device_sessions_redis_test.rs`,
  `auth_security_test.rs::redis_adapter_shares_limits_between_instances_when_configured`)
  were the same small pattern (env unset → bare `return`), so they were fixed with
  `redis_url_or_skip` as the card allows. Qdrant: **no test file references Qdrant
  at all** — there is nothing to skip silently; the missing coverage itself is a
  follow-up candidate for whichever task owns vector search tests, recorded here.
- 2026-09-30 `docs/stress-testing.md` left untouched, because it documents the
  `stress` binary, not the test suite; the discoverable path for a reader is
  marker line → grep → `tests/service_skip/mod.rs` module docs → compose comments.
- 2026-09-30 **Boundary deviation, flagged for the lead:** the commit contains a
  three-line mechanical `rustfmt` rewrap of `tests/integration/web_client.rs:46`,
  a file this task does not own. Reason: the line (from the lead's `f044c5d`)
  fails `cargo fmt --all -- --check` at the unmodified base `d12aae2` on this
  machine (rustfmt 1.9.0-stable, no rust-toolchain pin in the repo), so without
  the rewrap no commit of this branch can be green on its own. It is pure
  rustfmt output, zero semantic change; drop it on merge if it is fixed on main
  first.
- 2026-09-30 The "print how many tests skipped" hint is per-test marker lines plus
  a documented `grep -c`, not an end-of-run summary line, because `cargo test
  --all-targets` runs 64 independent test binaries with no shared end-of-run hook;
  a real aggregator would need a custom harness or a `ctor`-style dependency
  (new dependency = integration-lead review, and disproportionate for an S card).
  16 identical-prefix lines are countable at a glance and by machine.
- 2026-09-30 **Acceptance deviation (integration lead, recorded as instructed):**
  the card's "stop the postgres container and watch the output" is replaced by
  env-var-based verification, because a parallel agent shares the
  `chatroom-local-*` containers. Equivalence under the new design: tests never
  probe for PostgreSQL, so the container's state is only ever observed when
  `TEST_POSTGRES_ADMIN_URL` is set — and then a stopped container is the
  verified loud-panic path (c), while with the var unset a stopped container is
  byte-for-byte identical to no container at all, the verified visible-skip
  path (a). There is no third state left in which stopping the container could
  change behavior.

## Residual risk

- Markers bypass libtest capture by writing to the raw fd; if a future Rust
  release routes `Stderr` writes through test capture, the markers would go
  silent again. The acceptance greps in Verification are the canary.
