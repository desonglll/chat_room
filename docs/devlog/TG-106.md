## Frozen interface

Module `packages/web/src/features/chatInfo/` — public surface is `index.ts`:

- `ChatInfoPanel(props: ChatInfoPanelProps)` —
  `{ chatId; client: ApiClient; onClose(); onSearchInChat?(chatId); closing?; onExited?(); sources?: ChatInfoSourceOverrides }`.
  Root element is `<aside class="tg-info tg-chatinfo">`, so the shell's existing `.tg-shell > .tg-info`
  column/overlay rules keep placing it. `data-closing` marks the exit slide.
- `features/shell/InfoPane.tsx` (now owned here) is the thin mount: `InfoPane({ onSearchInChat? })`, reads
  `uiStore.activeChatId` / `activePanel === 'chatInfo'` (contract unchanged), plays the exit slide when the
  shell renders it unconditionally (see patch list), and installs `watchPanelAnchor(uiStore)` at module scope.
- `selectInfoHeader(input) → InfoHeaderModel | null` and `infoVariant(chatType)`: pure; the variant is
  `private` / `group` (group + supergroup) / `channel`, decided by `chat_type` only.
- `holdMessageListAnchor(root?, ms?)`, `watchPanelAnchor(store, hold?)`: the layout-linkage guard.
  DOM contract consumed from TG-101: `.tg-shell__main [data-virtuoso-scroller]` and `[data-row-key]`.
- `SharedTabId = 'media' | 'files' | 'links' | 'voice' | 'gif'`; groups add a `members` tab first.

HTTP consumed (all existing, all authorised per request server-side; nothing new server-side):

| Tab / feature | Endpoint | Client-side narrowing |
| --- | --- | --- |
| media | `GET /api/chats/:id/files?kind=all` | image/video by `attachmentKind`, minus `image/gif` |
| files | `GET /api/chats/:id/files?kind=all` | `attachmentKind === 'file'` minus `audio/*` (keeps SVG, which `kind=file` would drop) |
| voice | `GET /api/chats/:id/files?kind=file` | `audio/*` |
| gif | `GET /api/chats/:id/files?kind=image` | `image/gif` |
| links | `GET /api/chats/:id/messages/search?q=http` | URLs via the bubble's `linkify`; cursor = last message id of a full page |
| members | `GET /api/chats/:id/members` | active only; owner, admins, online, name; 50-row client pages |
| header (private) | `GET /api/users/:id` | bio = `signature` |
| notifications | `GET/PATCH /api/conversations/:id/preferences` | on = `{notification_level:'all', muted_until:null}`, off = `{notification_level:'none'}` |

## Decisions

- 2026-10-01 Every tab has its own vanilla zustand pager (`sharedPager.ts`) created per chatId, rather
  than one store with a tab map, because the acceptance is "独立分页": a tab component subscribes only to its
  pager and a loadMore can never touch another tab's cursor (tested).
- 2026-10-01 Narrow tabs (voice, GIF, media, files) filter client-side with `filteredSource` (up to 4 raw
  pages until 12 survivors) instead of adding `kind=` values server-side, because Rust is owned by other
  active agents; the gap is written up below for M2/M4.
- 2026-10-01 Links come from the chat's own message search (`q=http`) + `linkify`, not a scan of loaded
  history, because search is server-filtered, keyset-paginated and re-authorised; the tab lists exactly
  what the bubble linkifies.
- 2026-10-01 One scroll column with a sticky tab strip (Telegram's layout) and per-tab remembered scroll
  offsets, rather than five nested scroll boxes, because nested scrollers under a profile header leave a
  tiny scroll area on short windows. Visited panels stay mounted (`hidden`), so pages and DOM survive tab
  switches; `.tg-chatinfo__shared { min-height: 100% }` lets the strip stick even on a short tab, which
  is what makes the offset restore possible (measured: links 900 → files 342 (= stick point) → links 900).
- 2026-10-01 Layout linkage: the grid column is allocated at once and the panel slides in with a
  transform (`--tg-duration-spring`/`--tg-ease-spring`); nothing animates layout per frame. The one width
  change re-wraps bubbles (measured 63 px drift at 1280 px + 480 px sidebar without a guard), so
  `panelAnchor.ts` pins the topmost row (or the bottom, when at the bottom) and corrects scrollTop from
  ResizeObserver callbacks for 700 ms — TG-101's `usePrependAnchor` technique. The pin is taken in a
  synchronous `uiStore.subscribe`, because by the time any component effect runs the new layout exists and
  the old offset is gone. It is installed at `InfoPane.tsx` module scope so it works with today's
  conditional mount too.
- 2026-10-01 The guard lives here and reaches the list through TG-101's DOM contract instead of editing
  `features/messageList`, because that path is not on this card. A later owner may move it into the list
  as a generic "width change keeps the anchor" (sidebar drag and window resize would benefit).
- 2026-10-01 Group header count = max(`chats.member_count`, live presence members, the fully loaded member
  list), because `member_count` is never incremented on join today (seed: a 6-member group reads 1;
  TG-201 owns "member_count 投影的事务内维护"). Online count = members whose presence status is `online`,
  the same source as each member row, so header and list never disagree (the WS `participants` list
  reported 6 online while every row said 离线).
- 2026-10-01 Reduced motion: slide → opacity keyframes (not `animation: none`), so `animationend` still
  fires and the exit unmount path is identical; a 700 ms timer is the safety net.
- 2026-10-01 No new dependencies; `motion` not used — two CSS keyframes read the spring tokens.

## Backend gaps (for M2/M4 owners — not implemented here, Rust untouched)

- `GET /api/chats/:id/files` accepts only `kind=all|image|video|file`
  (`src/attachments/file_handlers.rs`). Needed: `kind=media` (image+video, excluding GIF), `kind=gif`,
  `kind=voice` (audio, and M4 voice notes, which will need a message-type discriminator rather than MIME),
  `kind=document` (non-media, non-audio, including `image/svg+xml`). Until then the client fetches up to 4
  pages of 100 per "load more" on a sparse tab.
- No link index: links are derived from `GET /api/chats/:id/messages/search?q=http`. It misses bare
  `www.` links (by design, the bubble does not linkify them either) and costs a LIKE scan. M4's link
  preview task (TG-408) is the natural owner of a `message_links` projection + `GET /api/chats/:id/links`.
- `GET /api/chats/:id/members` returns every row in one response; the client pages it in 50s. TG-201 owns
  the server cursor; only `memberSource.ts` changes then.
- `chats.member_count` is not maintained on join/leave (seeded group of 6 reads 1). TG-201.
- Channels: subscriber count reads `member_count`; M2 must keep that projection correct for channels.

## Residual risk

- `panelAnchor.ts` couples to TG-101's DOM (`[data-virtuoso-scroller]`, `[data-row-key]`,
  `[data-testid="virtuoso-item-list"]`). If the list renames them the guard silently does nothing (the
  panel still works; the list may drift on re-wrap). A test pins the subscription, not the DOM contract.
- The guard runs for 700 ms; an image decoding later than that inside the viewport can still shift rows
  (the same limit TG-101's guard has).
- Sparse tabs on a very large chat: `filteredSource` stops after 4 raw pages (400 files) per load; a
  chat with thousands of images and no voice notes needs several scroll-triggered rounds to prove "empty".
- The exit slide needs patch item 3; until then closing is an instant unmount (the anchor guard still
  holds on close — measured).
