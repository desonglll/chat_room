## Frozen interface

- `GET /api/messages/search` `content_type` gains `media` (photo+video, not round/sticker/GIF),
  `document` (files that are not media/audio/voice/sticker/GIF), `link` (http/https in text),
  `music` (audio files that are not voice), `voice` (voice + round video). `all/text/file/image/
  video/audio` keep their meaning. Results report `content_type: "voice"` for voice/round.
- `q` now also matches the attachment's file name.

## Decisions

- Seven tabs: 聊天 (client-side chat filter + public results, as before), 消息, 媒体, 链接, 文件,
  音乐, 语音; each message tab is one server filter with its own cursor and its own fetch, so
  tabs paginate independently (switching tabs starts that tab from page one).
- Authorization stays read-time: results come from a join on the viewer's *active* membership,
  never from an index of what was once visible — leaving a chat removes its results (tested).
- Sender filter lists the senders present in the loaded results (Telegram's "from" picker without
  a member directory call); date range is day-granular local time (existing core helper).
- Recent searches: per browser (`tg.search.recent.v1`, newest first, case-insensitive dedupe,
  max 10), recorded when a result is opened; suggestions = recent searches extending the typed
  text (or the latest three when nothing new is typed).
