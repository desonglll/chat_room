## Decisions

- 2026-09-30 **TTL 6 s → 5 s, sender refresh 4 s.** Acceptance demands a clear within 5 s of the
  last frame; Telegram's own pair is 6 s/5 s. Keeping a 1 s gap between refresh and TTL (instead of
  refreshing at 5 s) means one late frame does not flicker the receiver's line.
- 2026-09-30 **Display filters by the clock, not by the store purge.** `summarizeTyping` ignores
  indicators older than TTL, so the text is gone at exactly 5.000 s even though
  `chatSession.ts` (features/chat, not mine) purges the store at TTL + 50 ms.
- 2026-09-30 **One shared ticker with exact wake-ups** (`nowTicker.ts`) instead of per-row timers
  or a fast poll: 5 s regular period for minute-granular last-seen, plus a wake at the earliest
  typing expiry (wake source = presenceStore). A 1 s poll would have cleared typing up to 6 s late.
- 2026-09-30 **Mixed actions across several users fall back to 正在输入** (Telegram Android's
  multi-user behaviour); naming one person's action for the group would misdescribe the others.
  Same action for all keeps its own copy ("A 和 B 正在录音").
- 2026-09-30 **Chinese spacing:** "A 正在输入", "A 和 B 正在输入", "A 和其他 2 人正在输入" (the counted
  phrase joins the verb, matching the lead's spec).
- 2026-09-30 **`empty` status and unknown user → 离线, not 很久以前上线.** TG-007's server sends `empty`
  when it has no persisted last-seen (TG-007 devlog), so "a long time ago" would be false.
- 2026-09-30 **Minutes before calendar days**: 40 minutes across midnight reads "40 分钟前上线", as in
  tdesktop's `OnlineText`. Yesterday is computed via the calendar, not now − 24 h (DST-safe).
- 2026-09-30 **Group online count** = distinct connected `members` ∪ `statuses` with `online`, shown
  only when > 1 (Telegram hides "1 online", which is just you). Channels read "N 位订阅者".
- 2026-09-30 **`typing` with an empty preview is sent as `cancel`**, because TG-007 keeps the legacy
  rule "empty content + typing = stopped"; sending it would contradict itself. Non-`typing` actions
  get a keep-alive on the injected clock (a held record button makes no further calls); `typing`
  does not (a paused typist should expire).
- 2026-09-30 **Private peer** = first participant/member ≠ current user of that chat's presence
  snapshot; the status comes from the account-wide `users` map so it also resolves for rows whose
  socket is not open once any chat reported it.
- 2026-09-30 Hooks use `useSyncExternalStore` over presence/chatList/auth stores + ticker with a
  value-compared snapshot cache, so a row re-renders only when its string changes.
- 2026-09-30 Dots animation: opacity + scale pulse on `--tg-duration-loop`; reduced motion keeps only
  a slower opacity breath (a loop collapsed to 1 ms would strobe — same reasoning as Spinner.css).

## Residual risk

- `offline.last_seen` is only real for users who disconnect while we watch; on connect TG-007 reports
  `online`/`empty` only, so most offline peers read 离线 until TG-505 persists last-seen.
- `chatSession.ts` still re-sends text previews every 1 s while keys are pressed; fine for the 5 s TTL.
- Regular tick is 5 s: minute boundaries of last-seen text can lag up to 5 s (typing expiry is exact).
- Statuses are per chat socket; a chat-list row for a chat without an open socket sees typing only
  if some future account-wide channel delivers it (none exists today).
