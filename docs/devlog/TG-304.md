### Storage (`20261201000003`, SQLite + PostgreSQL)

| Table | Key | Notes |
| --- | --- | --- |
| `message_entities` | `(message_id, position)` | `message_id` → messages CASCADE; `entity_type` TEXT; `offset_utf16`, `length_utf16` INTEGER; `custom_emoji_id` → `custom_emoji(sticker_id)` SET NULL; `url`, `user_id`, `language` nullable (reserved for text_link / mention_name / pre) |
| `user_emoji_status` | `user_id` | → users CASCADE; `custom_emoji_id` → `custom_emoji(sticker_id)` CASCADE; `expires_at` nullable; `updated_at` |

### `MessageEntity` wire shape (history `StoredMessage`, WS `broadcast`, `message`, `edit`, `message_edited`)

```jsonc
{ "type": "custom_emoji", "offset": 0, "length": 2, "custom_emoji_id": "uuid" }
// type ∈ custom_emoji | bold | italic | underline | strikethrough | spoiler | code | pre | text_link | mention_name
// offset/length are UTF-16 code units of `content` (JS string indices, Telegram semantics)
// url (text_link, http/https only), user_id (mention_name), language (pre) — omitted when absent
```

- `entities` is **omitted when empty** on every server frame and on `StoredMessage`, so every
  frozen byte-level snapshot is unchanged; clients read absent as `[]`.
- Client → server `message` / `edit` frames accept optional `entities`. The server shifts them
  for the leading whitespace it trims, then keeps only valid ones (in bounds, length > 0,
  known type, custom emoji exists, no two custom emoji overlap, ≤ 100) — invalid entities
  are dropped, the text is never refused because of them.
- An `edit` replaces the entity list (absent = none); `message_edited` carries the new list.
- Recalled messages carry no entities for viewers who cannot see the content.

### HTTP (bearer-authenticated)

| Method + path | Body | Response |
| --- | --- | --- |
| `GET /api/custom-emoji/installed` | — | 200 `InstalledStickerSets` restricted to `set_type = custom_emoji` (install/reorder/archive stay on `/api/stickers/installed/*`) |
| `GET /api/custom-emoji?ids=a,b,…` | ≤ 200 ids | 200 `[CustomEmoji]` — unknown ids omitted; removed ones still resolve (sent messages keep rendering) |
| `PUT /api/users/me/emoji-status` | `{custom_emoji_id, expires_at?}` | 200 `EmojiStatus`; 400 `custom_emoji_not_found` / `invalid_expiry` |
| `DELETE /api/users/me/emoji-status` | — | 204 |
| `GET /api/users/emoji-statuses?ids=a,b,…` | ≤ 200 ids | 200 `[EmojiStatus]` — only the caller and accounts sharing an active chat with the caller; expired statuses are never returned |

```jsonc
// CustomEmoji — same capability-URL authorization as a sticker catalogue file
{ "id": "uuid", "set_id": "uuid", "set_short_name": "cats", "emoji": "😺",
  "format": "webp|tgs|webm", "width": 100, "height": 100,
  "file_url": "/api/stickers/<id>/file?key=<k>" }
// EmojiStatus
{ "user_id": "uuid", "custom_emoji_id": "uuid", "expires_at": "…|null", "emoji": CustomEmoji }
```

### Web exports (`packages/web/src/features/customEmoji/index.ts`)

- `<EmojiStatus userId size? />` — renders nothing when the user has no (visible) status.
- `<CustomEmoji id fallback size? />` — inline image with `alt = fallback`; unknown / unresolved → the fallback text.
- `<CustomEmojiTab onPick />` — picker tab over the installed custom emoji sets; `onPick({ id, emoji })`.
- `<EmojiStatusPicker onDone? />` — sets / clears the viewer's status with an expiry.
- `registerAnimatedEmojiRenderer(format, Component)` — TG-301's TGS/WebM renderer plugs in here.
- `EntityTextContent` registered as message kind `entity_text` by `register.ts` (side-effect import).
- `@tg/core`: `MessageEntity`, `parseMessageEntities`, `segmentEntityText`, `insertCustomEmoji`, `reconcileEntities`; `customEmojiApi`.
