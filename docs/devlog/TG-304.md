### Storage (`20261201000003`, SQLite + PostgreSQL)

| Table | Key | Notes |
| --- | --- | --- |
| `message_entities` | `(message_id, position)` | `message_id` → messages CASCADE; `entity_type` TEXT; `offset_utf16`, `length_utf16` INTEGER; `custom_emoji_id` → `custom_emoji(sticker_id)` SET NULL; `url`, `user_id`, `language` nullable (reserved for text_link / mention_name / pre) |
| `user_emoji_status` | `user_id` | → users CASCADE; `custom_emoji_id` → `custom_emoji(sticker_id)` CASCADE; `expires_at` nullable; `updated_at` |

### `MessageEntity` wire shape (history `StoredMessage`, WS `broadcast`, `message`, `edit`, `message_edited`)

```jsonc
{ "type": "custom_emoji", "offset": 0, "length": 2, "custom_emoji_id": "uuid" }
// type ∈ custom_emoji | bold | italic | underline | strikethrough | spoiler | code | pre | text_link | mention_name
// offset/length are UTF-16 code units of `content` (JS string indices, Telegram semantics)
// url (text_link, http/https only), user_id (mention_name), language (pre) — omitted when absent
```

- `entities` is **omitted when empty** on every server frame and on `StoredMessage`, so every
  frozen byte-level snapshot is unchanged; clients read absent as `[]`.
- Client → server `message` / `edit` frames accept optional `entities`. The server shifts them
  for the leading whitespace it trims, then keeps only valid ones (in bounds, length > 0,
  known type, custom emoji exists, no two custom emoji overlap, ≤ 100) — invalid entities
  are dropped, the text is never refused because of them.
- An `edit` replaces the entity list (absent = none); `message_edited` carries the new list.
- Recalled messages carry no entities for viewers who cannot see the content.

## Decisions

<!--
  Every non-obvious choice, with the reason. The reason is the part that
  survives; "switched to X" without "because Y" is worthless to the next agent
  and will be re-litigated.
-->

- 2026-10-01 Entities live in their own table `message_entities`, not a JSON column on `messages`, because every message loader already funnels through `attach_message_reactions` (TG-302's hook), so one batched query adds them to history, replay, search and live delivery without touching `messages/store.rs` (at its 457-line baseline) or its `MESSAGE_SELECT`; rows are also indexable by `custom_emoji_id`.
- 2026-10-01 Entities are written in the same transaction as the text (`store_message`, `edit_message`), because live delivery is a DB poller: two separate writes let a poll deliver text without entities. `store_message` gained an `entities` parameter (its only other caller, `knowledge/store_tests.rs`, passes `&[]`).
- 2026-10-01 Offsets are UTF-16 code units (Telegram and JS semantics) and the server shifts client entities by the UTF-16 length it trims off the front, so a client never needs to know about the trim.
- 2026-10-01 Invalid entities are dropped, never the message: the WS `message` frame has no error channel, and losing a user's text over a formatting detail is worse than losing the formatting.
- 2026-10-01 Unknown entity types from a client are dropped, but the server already accepts and stores the formatting types (bold/italic/underline/strikethrough/spoiler/code/pre/text_link/mention_name) with their fields, so the renderer that later draws them needs no migration or protocol change. Only `http(s)` links are kept.
- 2026-10-01 `entities` is omitted (`skip_serializing_if = Vec::is_empty`) on every frame and on `StoredMessage`, so all frozen byte-level snapshots are unchanged and old clients see the fallback emoji inside `content`.
- 2026-10-01 An edit replaces the entity list (absent = none) and `message_edited` carries it, because offsets into the old text are meaningless for the new one. Frozen clients keep sending edits without entities, which correctly clears them.
- 2026-10-01 Resolve works for any signed-in account whether or not it installed the set (Telegram semantics; TG-302 made sets public by short name). "Uninstalled/unknown falls back" is implemented as: unknown id, ordinary sticker, removed emoji, failed image, or animated format without a renderer → the fallback character that is part of the text. Removed emoji do not resolve because TG-302's catalogue file URL 404s for removed stickers.
- 2026-10-01 Emoji status visibility = self + accounts sharing an active chat membership, checked in the read query; expiry filtered at read time. That is exactly who can see the name the status decorates. No realtime push: the client re-checks every 60 s and hides an expired status locally.
- 2026-10-01 Copy: browsers disagree on whether a copied `<img>` contributes its `alt` to `text/plain` (Chrome drops it), so a copy handler rewrites `text/plain` whenever the selection contains a custom emoji, using the `data-custom-emoji` marker; selections without one keep the browser default. The walk is written against a structural `CopyNode` so it is testable without a DOM.
- 2026-10-01 The renderer re-validates entities against the text (`parseMessageEntities`, custom emoji must cover pictographic characters) because `messageStore.applyEdit` (TG-100) does not yet copy `entities`; a stale entity then falls back to plain text instead of drawing an emoji over a word.
- 2026-10-01 PostgreSQL entity columns are BIGINT (the first PG run caught INTEGER decoded as `i64`; the poller swallowed the error so the broadcast never arrived).
- 2026-10-01 Resolution and status lookups go through a small batching cache in the feature (`batchCache.ts`) instead of a core store: many glyphs render at once, and a new `packages/core/src/stores/*` file was outside the card.
- 2026-10-01 Module layout: `src/stickers/custom_emoji.rs` is the module root with submodules in `src/stickers/custom_emoji/` (one file would exceed the 350-line warning).

## Residual risk

- Out-of-card edits to `src/messages/{text_store,actions,reactions}.rs`, `src/realtime/{frames,inbound,outbound,protocol}.rs`, `src/models.rs` and core `types/` may conflict with TG-406 (polls) / TG-100 merges; all are additive.
- `edits_after` now runs one extra batched query per poll that returns edits (not per idle poll).
- The copy handler copies TG-103's invisible meta-spacer text (the time) when a selection runs to the end of a bubble. That is TG-103's spacer (same for plain text in browsers that copy hidden text); `user-select: none` on the spacer would fix both.
- Composer-side entity tracking diffs text by common prefix/suffix; a single input event that changes both ends (programmatic replace-all) drops entities — correct but lossy.
- Emoji status has no realtime push; peers see a change within 60 s (cache TTL). Status visibility follows chat co-membership, not TG-505's privacy matrix — TG-505 may want to add a privacy rule.
- `forward_message` does not copy entities (a forwarded message shows fallback emoji), same as TG-302's forwarded-sticker gap; `store.rs` is at its size baseline.
- Resolve returns only live emoji: a message whose emoji was later removed from its set shows the fallback (TG-302's file URL 404s for removed stickers).
