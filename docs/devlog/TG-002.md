### Workspace layout

Root `package.json` declares `workspaces: ["packages/*"]`. `web/` (old Vue client) is
**deliberately outside** the workspace and keeps its own `web/bun.lock`, so
`cd web && bun install && bun dev` stays independently runnable until TG-602 deletes it.

Toolchain: bun 1.3.14, TypeScript 5.9.3, Vite 8, React 19.3, prettier 3.6.2.
Shared compiler options live in `tsconfig.base.json`; each package's `tsconfig.json`
extends it. There is no root `tsconfig.json` (see Decisions).

### Per-package scripts (frozen — CI calls these by name)

Every package implements exactly these three, so `bun run -F '*' <script>` works:

- `typecheck` → `tsc --noEmit`
- `lint` → `prettier --check <paths>`
- `test` → `bun test`

Plus `format` (`prettier --write`) everywhere. `@tg/core` additionally has `boundary`, which
runs only the boundary test so CI can show it as its own named gate; the same test also runs
inside `@tg/core`'s `test`. `@tg/web` additionally has `dev` / `build` / `preview`.

Note: `bun test` **exits 1 when a package has no test files** (verified on bun 1.3.14). Every
package therefore must keep at least one test file.

### The boundary rule (architecture.md §2, decision D-002)

Enforced by `packages/core/test/platformBoundary.test.ts` against
`packages/core/test/platformBoundary.ts` (the scanner). Exact rule, as implemented:

1. **`forbidden-module`** — no module specifier in `packages/core/src/**/*.{ts,tsx,mts,cts}`
   may equal, or start with `<name>/`, any of: `react`, `react-dom`, `@tg/ui`, `@tg/web`.
   Specifiers are found in `import … from 'x'`, `export … from 'x'`, bare `import 'x'`,
   `import('x')` and `require('x')`. Type-only imports count as violations too.
   Sibling names are not violations: `react-native`, `reactive-thing` pass.
2. **`forbidden-global`** — no bare identifier `window`, `document`, `localStorage` or
   `navigator` may appear in `packages/core/src`. `globalThis.window` and `globalThis?.window`
   count. A property access on something else (`state.document`) and a longer identifier
   (`documentTitle`) do not.
3. `packages/core/package.json` may not list any forbidden module in `dependencies`,
   `devDependencies` or `peerDependencies`.

Comments and string/template-literal **contents** are stripped before both checks, so a
comment or a string may mention these names. Template **interpolations** (`` `${window.x}` ``)
are scanned as code. Two deliberate over-strictnesses, both covered by a named test:
regular-expression literals are scanned as code, and a *declaration* named after a forbidden
global trips the rule (`interface Host { document: unknown }` fails; `state.document` does
not). If TG-011 needs a property called `document`, rename the property — do not loosen the
rule.

Secondary, type-level guard: `tsconfig.base.json` sets `lib: ["ES2022"]` with **no `DOM`**.
`packages/ui` and `packages/web` add `DOM` back; `packages/core` does not. This net is
**partial** — measured, not assumed: it catches `window` and `document`, but `@types/bun`
declares `localStorage` and `navigator`, so those two produce no error or a different one. The
executable test is the gate; this is only a faster signal for two of the four globals.

**These two files must not be deleted or weakened.** TG-011 owns `packages/core/**` and can
therefore reach them; if the rule needs to change, that needs a `docs/tg/decisions.md` entry,
because it is the entire mechanism keeping the React Native door open.

- 2026-09-30 Boundary check is an **executable bun test that scans source text**, not an
  ESLint config, because the task's whole value is that it fails in CI. An ESLint
  `no-restricted-imports` rule only fires if someone remembers to keep ESLint wired up and
  covering the right files; a test in `bun test` fails the moment the file lands. Also: no
  ESLint is installed in this repo today, so a lint-based answer would have meant a new
  dependency with no other user.
- 2026-09-30 The scanner is a **pure function over source text** (`scanSource(file, source)`)
  with unit tests over inline fixtures, rather than an inline blob inside the test, because
  the check itself can be wrong. Nine positive and five negative fixtures prove it fires and
  prove it does not fire on comments, strings, `state.document` or `react-native`.
- 2026-09-30 The test asserts `collectSourceFiles(src).length > 0` before asserting zero
  violations, because a scan that silently walks an empty directory passes forever. That
  assertion is the difference between a gate and false confidence.
- 2026-09-30 Comments and string contents are stripped, but **regex literals are not**. A
  correct regex-vs-division lexer needs previous-token lookback and is a bug farm; leaving
  regex bodies as code can only produce false positives (over-strict), never false negatives.
  Over-strict is the safe direction for this particular rule.
- 2026-09-30 Template-literal interpolations **are** scanned. `` `${window.origin}` `` is a
  real way to touch a DOM global and blanking the whole template would have been a genuine
  false negative.
- 2026-09-30 Type-only imports of `react` count as violations, even though they emit nothing,
  because they still make `packages/core` compile-time dependent on React's types — which is
  exactly what would have to be undone for React Native.
- 2026-09-30 A declaration named after a forbidden global (`interface Host { document: … }`)
  is reported rather than excluded, and there is a test asserting that. Excluding it would mean
  skipping occurrences followed by `:`, which would also skip `cond ? window : other` — a real
  global read. Over-strict costs a rename; under-strict silently reopens the hole. This one
  cost a fixture rewrite during development: the first version of the test asserted the
  opposite and failed, which is how the behaviour got pinned down instead of guessed.
- 2026-09-30 `lib: ["ES2022"]` with no `DOM` in `tsconfig.base.json`, re-added only in
  `ui`/`web`. Measured rather than assumed, and it is only a **partial** net: with the
  violating fixture in place `tsc --noEmit` reported `TS2304: Cannot find name 'window'` and
  `TS2584` for `document`, but said nothing about `localStorage` and only an unrelated
  `TS2339` about `navigator.onLine`, because `@types/bun` declares both of those globals. So
  the type system covers two of the four; the test covers all four. Recorded because "tsc will
  catch it" is exactly the kind of false confidence this task was told to avoid.
- 2026-09-30 No root `tsconfig.json`, only `tsconfig.base.json`. A solution-style root file
  needs `references`, `references` needs `composite: true`, and `composite` cannot coexist
  with `noEmit` — so it would have forced declaration emit on packages that are consumed as
  source. Per-package `tsc --noEmit` via `bun run -F '*' typecheck` gives the same coverage
  with none of that.
- 2026-09-30 Packages are consumed as TypeScript source (`exports` → `./src/*.ts`), with no
  build step for `core`/`ui`. Vite and bun both read `.ts` directly; a build step would add
  ordering constraints between packages for zero benefit while everything is internal.
- 2026-09-30 prettier 3.6.2 pinned to the version already in `web/devDependencies`, and its
  config lives in the **root `package.json` `"prettier"` key** — not a root `.prettierrc`.
  Reason: `.prettierrc` at root is outside this task's allowed paths, and the config values
  are copied from `web/.prettierrc.json` (printWidth 120, no semicolons, single quotes) so the
  new packages read like the rest of the repo. `web/.prettierrc.json` still wins for `web/`
  files because prettier stops at the nearest config, so this cannot change `web`'s
  `format:check` result.
- 2026-09-30 `lint` is `prettier --check`, not a real linter, because adding ESLint is a new
  dependency with no present owner (AGENTS.md). The name `lint` is kept because the roadmap
  card and CI speak of a lint step; the script is honest about what it runs.
- 2026-09-30 `@tg/core`'s `lint` does **not** also invoke the boundary test, even though the
  rule is lint-shaped. It is already in `test` and in its own CI step; chaining it into `lint`
  made CI execute the same 19 assertions three times per run for no extra signal.
- 2026-09-30 `.gitignore` needed no change. `git check-ignore -v` confirms the existing
  `/node_modules/`, `/packages/*/node_modules/` and `/packages/*/dist/` entries already cover
  everything `bun install` and `vite build` produce (bun does create a `node_modules` in each
  package for its `.bin` shims, and line 17 catches those). Editing it would have been noise.
- 2026-09-30 TypeScript pinned to **5.9.3**, not the current latest 7.0.2, because
  `docs/tg/README.md` locks "React 19 + TypeScript 5.9". Changing it needs a decisions.md
  entry.
- 2026-09-30 `@vitejs/plugin-react@6` is included rather than relying on Vite's built-in
  esbuild JSX transform, because without it there is no React Fast Refresh and TG-012 would
  have to add it immediately. Its `oxc-transform-react` / babel peers are optional and are not
  installed.
- 2026-09-30 `@tg/ui`'s `.` entry is `src/primitives/index.ts`, not `src/index.ts`, because
  this task may only write `packages/ui/src/primitives/**`. TG-010 owns `packages/ui/**` and
  may promote a `src/index.ts` barrel; if it does, it must update the `exports` map too.
- 2026-09-30 `packages/ui/package.json` already declares `"./tokens/*": "./src/tokens/*"`
  although nothing exists there yet. TG-009's allowed paths are `packages/ui/src/tokens/**`
  and `design/**` — it **cannot** edit `packages/ui/package.json`, so it would have been
  blocked from exposing its CSS. Pre-declaring the entry unblocks it without this task
  touching `src/tokens/`.
- 2026-09-30 `VisuallyHidden` is the single example primitive. It is deliberately **not** one
  of the 19 atoms TG-010 owns, so there is no collision, and it needs no design tokens (TG-009
  has not run yet) while still proving the JSX pipeline and the `@tg/ui` → `@tg/web` import
  path compile.
- 2026-09-30 `packages/web/test/workspaceWiring.test.ts` dynamically imports `@tg/core` and
  `@tg/ui` instead of `packages/web` importing an invented `@tg/core` symbol. It proves
  workspace resolution really works at runtime without this task inventing API that TG-011
  would then have to delete.
- 2026-09-30 `packages/web` dev server is pinned to port 5174 so the old `web/` client (5173)
  and the new one can run side by side, which architecture.md §6 explicitly wants during
  M0–M5 behaviour comparison.
- 2026-09-30 Root `bun.lock` is committed even though it is not literally in this task's
  allowed-path list: creating a bun workspace necessarily produces it, it is the generated
  artefact of the root `package.json` this task does own, and CI's

## Residual risk

<!-- What a reviewer should distrust. Empty is a valid answer only if you looked. -->

- The boundary scanner is a lexical scanner, not a type-aware analysis. It can be defeated on
  purpose: `const g = eval('window')`, `Function('return document')()`, a re-export chain
  through a third package, or a string assembled at runtime. It stops the realistic accident
  (someone writes `localStorage.getItem` out of habit), not a determined bypass. Making it
  type-aware would mean a TypeScript-AST-based check and a new dependency.
- `packages/core/src/**` is currently five `export {}` barrels, so the real-scan test walks 6
  small files. The `files.length > 0` assertion stops it from degenerating into a no-op, but
  the scanner's behaviour on realistic core code is only proved by its inline fixtures until
  TG-011 lands. A reviewer should re-read the fixture list, not just the green tick.
- `@tg/ui/tokens/*` is declared in `exports` but `src/tokens/` does not exist. Importing it
  today throws at resolve time. That is intended (TG-009 creates the files) but it is an
  export entry pointing at nothing until then.
- The scanner is over-strict in one way TG-011 will plausibly hit: a declaration named after a
  forbidden global (`interface HostCapabilities { localStorage: StorageLike }`) is reported.
  That is tested and intended, but it is a trap if you read only the rule summary. Name
  injected capabilities `storage` / `clock` / `socket`, not after the browser global.
- `bun run -F '*'` matching only the three workspace members was verified by running it, not
  assumed. Root scripts still use the narrower `-F '@tg/*'` so that even a future bun release
  that includes the root package cannot recurse.
- `packages/web` has no `/api` dev proxy yet, so the page cannot talk to the Rust server in
  `vite dev`. TG-012 needs to add one; nothing here is broken, but do not read "the page
  loads" as "the client works".
