## Defects found (two real accounts, real Chromium, `packages/web/test/e2e/contacts.e2e.mjs`)

1. **加好友后无法聊天 — «慢速模式已开启 · 还需等待» locks the composer of chats without slow
   mode.** `useSlowMode` read `now` once at mount; after loading it set the deadline to
   `Date.now() + 0`, which lies after that stale `now`, and the ticker skipped deadlines already
   past. Result: a phantom wait equal to the time since the hook mounted, never ticking down —
   `canSend` false. Reproduced by switching away from the private chat and back: with the
   fix reverted, E2E step 6 times out; with it, passes. Fix: `slowModeWait()` returns 0
   whenever the chat has no slow mode or the viewer is exempt, and `now` refreshes whenever
   the deadline changes. Test: `slowMode/slowModeWait.test.ts` (old formula gives 120 s).
2. Contacts page never refreshed live — requests/accepts/removals needed a manual reload.
   `social_changed` now bumps `notificationsStore.socialRevision`; `useContacts` reloads on it.
   Test: `contacts/liveRefresh.test.ts`; E2E steps 3, 4, 7.
3. Search: a 1-char query (server 400) and a rate-limited search (429) both showed «没有找到».
   Now «至少输入 2 个字符» / «查找太频繁» / «查找失败». E2E step 10.
4. Search results went stale after acting on them (only «加为好友» re-ran the search); any
   successful change now re-runs it. Accepting an incoming request from search said
   «好友申请已发送» — now «已添加为好友».
5. Remark editor had no way out but submitting; Escape now cancels. E2E step 5.
6. Withdrawing a request gave no feedback; now «已撤回申请».
7. No way to block someone who is not yet a friend (Telegram allows it); search rows get «拉黑».

Already present, not changed: pending-request badge on the main-menu «联系人» entry
(`ChatListPane.tsx`, fed by `social_changed`).
